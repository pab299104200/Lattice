# MCP Surface Audit

This audit is the Phase 8 contract check for the cognitive workspace fork. It reconciles the MCP surface in `daemon/crates/lattice-daemon/src/rpc/mcp.rs` with [## MCP Surface](../plans/2026-05-16-cognitive-workspace-fork-plan.md#mcp-surface), [## MCP Tool Contract Principles](../plans/2026-05-16-cognitive-workspace-fork-plan.md#mcp-tool-contract-principles), [## Phase 8: Workflow Engine V2](../plans/2026-05-16-cognitive-workspace-fork-plan.md#phase-8-workflow-engine-v2), and the compatibility rules in [MCP Compatibility Policy](./2026-05-16-mcp-compatibility-policy.md). The canonical final inventory is [MCP Tool Reference](./2026-05-16-mcp-tool-reference.md).

Spec framing from [## MCP Surface](../plans/2026-05-16-cognitive-workspace-fork-plan.md#mcp-surface):

> Tool surface discipline: ten new memory tools is a meaningful cognitive load for clients. Before shipping Phase 8, audit whether `propose_memory_evolution` + `apply_memory_evolution` can collapse into a single tool with an `action` parameter, and whether `verify_memory` + `explain_memory` can be unified. The goal is the smallest surface that covers all assistant workflows. Consolidate before stabilizing the MCP contract.

## Audit findings

The Phase 8 surface keeps the required workflow vocabulary stable, adds the memory tools that introduce new assistant workflows, and collapses nominal memory tools where separate names would only split one lifecycle operation across multiple verbs.

| Decision | Rationale | Spec authorization | Shim policy | Shim-removal deadline |
|---|---|---|---|---|

## Decisions not to collapse

| Considered pair or group | Decision | Rationale |
|---|---|---|
| `get_context_capsule` and `get_docs_capsule` | Keep separate. | `get_context_capsule` anchors source-code pivots, symbols, tests, and nearby implementation context. `get_docs_capsule` anchors Markdown docs, sections, and code mentions. Combining them would force every discovery call to carry both source and docs ranking controls. |
| `get_backlinks`, `get_outgoing_links`, and `find_stale_docs` | Keep separate. | Backlinks answer inbound references, outgoing links answer outbound references, and stale-doc detection compares changed files or symbols against docs. They share graph substrate but expose different traversal directions and review intents. |
| `prepare_change` and `plan_edit` | Keep separate. | `prepare_change` is a first workflow tool for fix/add/refactor tasks once the area is known. `plan_edit` is patch-oriented and returns edit spans, affected callers, docs, and tests. Collapsing them would hide the distinction between change preparation and concrete edit planning. |
| `trace_scenario` and `diagnose_failure` | Keep separate. | `diagnose_failure` starts from compiler/test/runtime failure text. `trace_scenario` starts from behavioral descriptions and traces likely execution paths. Their inputs, diagnostics, and ranking signals differ. |
| `get_task_memory`, `search_memory`, and legacy `get_session_context` | Keep separate for now. | `get_task_memory` is task-scoped and working-memory-aware. `search_memory` is a required query workflow over stored memories. `get_session_context` is a legacy session-recall contract classified as `redesigned-with-shim` in the T02 policy. Collapsing them now would create a backward-incompatible request shape. |
| `consolidate_session` and `propose_memory_evolution` | Keep separate. | `consolidate_session` produces proposal ids from event episodes and consolidation categories; `propose_memory_evolution` applies or rejects specific memory-evolution proposals. Generation and decision remain distinct workflow boundaries for auditability. |
| `get_memory_metrics`, `get_event_trace`, and `get_session_metrics` | Keep separate. | `get_memory_metrics` reports Phase 9 memory/workflow signals with provenance, `get_event_trace` pages event envelopes, and `get_session_metrics` reports live assistant-session MCP metrics. They have different scopes, budgets, and response shapes. |
| `inspect_working_memory` and `get_working_set_context` | Keep separate. | `inspect_working_memory` reads task working-memory checkpoints. `get_working_set_context` compresses already-known files and symbols into a code/docs/test bundle. The identity type and operator question are different. |

## Reconciliation

The final advertised `tools/list` surface after Phase 8 contains the existing canonical workflow, graph, doc, memory, setup, and metrics tools plus ten Phase 8 memory entries, three of which are deprecated shims required for compatibility. `handle_tools_call` also accepts five callable-only legacy aliases from the T02 compatibility policy: `query_context`, `blast_radius`, `get_file_context`, `store_memory`, and `recall_memories`.

The required [## MCP Surface](../plans/2026-05-16-cognitive-workspace-fork-plan.md#mcp-surface) workflow tools are all present in [## Final tool list](./2026-05-16-mcp-tool-reference.md#final-tool-list): `get_context_capsule`, `prepare_change`, `plan_edit`, `trace_scenario`, `diagnose_failure`, `find_relevant_tests`, `impact_from_diff`, `get_docs_capsule`, `get_backlinks`, `expand_context`, `get_working_set_context`, `get_repo_playbook`, `search_symbols`, `search_memory`, and `record_workflow_outcome`.
