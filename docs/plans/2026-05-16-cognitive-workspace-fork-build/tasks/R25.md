This review certifies that the Phase 3 memory graph substrate satisfies every spec invariant before retrieval (Phase 4) starts depending on it. It confirms: the schema covers all 13 memory classes (including `CounterMemory` as a first-class record); links, evidence, accesses, and scores are first-class tables; stream classification and scope enforcement deny-by-default work as specified; the legacy migration imports cleanly and idempotently; CRUD plus the full verification-status state machine emits the right events; contradiction, supersession, stale state, and replay all behave correctly. The verdict gates R26 (contract gate) and Phase 4.

## Review procedure

1. Confirm `MemoryClass` enumerates all 13 spec variants and `CounterMemory` is present.
2. Confirm `MemoryRecord` has one field per spec-required attribute; cross-check the schema column inventory against the spec list.
3. Confirm the four first-class tables exist (`memory_links`, `memory_evidence`, `memory_accesses`, `memory_scores`) with the columns and indexes from spec §Storage Design.
4. Confirm `MemoryLinkType` enumerates all 11 spec variants; exhaustive `match` is used at write/read sites.
5. Confirm `MemoryStream` enumerates the seven streams and `classify_stream` is total over `MemoryClass`.
6. Confirm `ScopeFilter` is required on every read API (compile-time enforcement preferred; runtime `Underspecified` if not); confirm cross-scope leakage negative tests exist and pass.
7. Confirm the migration importer is idempotent, dry-runnable, restartable, and that every legacy column has a documented destination in the migration-guide column-mapping table.
8. Confirm the verification-status state machine matches the spec list and that disallowed transitions return typed errors.
9. Confirm contradiction tests exercise both the `Contradicts` link path AND the `CounterMemory` first-class-record path, and that the two are observably distinct (CounterMemory has its own id, evidence, scope, and verification status).
10. Confirm supersession chains preserve historical lookup and reject cycles.
11. Confirm replay tests show byte-equivalence between full replay and snapshot + tail, and that corruption returns a typed error without silent recovery.
12. Run the verification commands from tasks.json for T19–T24 from the repo root.
13. Audit for coding-standard regressions: file lengths, function lengths, error-swallowing, raw-SQL interpolation, missing tracing on transitions.
