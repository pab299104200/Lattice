# T17 — Phase 2 — Event log tests (ordering, replay, corruption, scoping, P99 ≤5ms hot path)

**Phase:** 2
**Type:** tests
**Model class:** balanced
**Depends on:** T11, T12, T13, T14, T15, T16
**Spec anchor:** [§Phase 2: Event Log Substrate](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-2-event-log-substrate)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task is the proof that the event log substrate honors every spec invariant under realistic conditions: events are totally ordered, the log replays back to identical state, corruption is detected and reported, scoped reads never leak across workspaces or branches, and the P99 write budget of ≤5ms on `prepare_change` and `get_context_capsule` is met. Without these tests, the Phase 2 Definition of Done cannot be claimed and Phase 3 (memory graph) is unsafe to start because its provenance depends on a trustworthy event log.

## Spec excerpts that drive this task

> "tests for ordering, replay, corruption handling, and workspace scoping"

> "event write adds no more than 5ms P99 to hot-path tool calls (`prepare_change`, `get_context_capsule`); large payloads spill to a side table rather than blocking the writer."

> "every high-level MCP workflow records task, retrieval, response, and outcome events"

> "No phase is complete until its failure paths are tested."

## Steps

1. In `events/replay_tests.rs`, write tests covering ordering and replay:
   - generate N (e.g. 1_000) events across multiple sessions/tasks/workspaces; assert `EventReader::stream` returns them in `event_id` order regardless of insertion concurrency.
   - assert monotonic `event_id` across two threads writing concurrently (use `Arc<EventWriter>` and `std::thread::scope`).
   - assert a full replay from snapshot + post-snapshot events reconstitutes identical graph + memory state to a no-snapshot full replay (uses T16 `Bootstrap::load`).
2. In `events/corruption_tests.rs`, write tests covering corruption detection:
   - write events, flip one byte in `event_payloads.bytes`, assert `EventReader::execute` returns `EventQueryError::PayloadCorruption { event_id, expected, actual }` and does not silently return wrong data.
   - flip one byte in `events.payload_hash`, assert the next read of that event reports corruption.
   - truncate the snapshot file mid-write (simulate crash), assert `Bootstrap::load` returns `BootstrapError::ContentHashMismatch` and the daemon falls back to the prior snapshot if one exists.
   - assert UPDATE on `events` table fails with the append-only trigger error from the engine, not from Rust-side validation.
3. In `events/budget_tests.rs`, write the P99 budget test:
   - construct a representative `prepare_change`-shaped payload (typical inputs based on the existing benchmark fixtures) and run `EventWriter::append` in a tight loop (e.g. 10_000 iterations) with batched flush, measuring per-call latency.
   - assert P99 ≤5ms on the in-process timer. Gate the test with `#[ignore]` so it does not run on every `cargo test`; the verification command runs it with `--include-ignored`.
   - repeat for a `get_context_capsule`-shaped payload.
   - emit the histogram (or selected quantiles) to a JSON file under `daemon/target/event_budget/` so R18 can cite it as P99 evidence.
   - run a payload-spill case (payload size > inline ceiling) and assert spill writes still meet P99 ≤5ms because of the batched flush.
4. Add a scoping test (kept in `replay_tests.rs` for proximity to the ordering tests, or split out): generate events across two workspace ids on the same store; assert that `EventReader` scoped to workspace A never returns workspace B events. Repeat for branch scoping.
5. Add a failure-path test in `replay_tests.rs`: a tool dispatched via the capture wiring (T15) that returns an error must still emit `ToolCalled` + `ToolResult(Error)` events; assert this via `EventReader::tail` on the session.
6. Use the temp-DB fixture pattern from T12 — every test owns its own DB path so tests can run in parallel without sharing state.
7. Where the spec's budget number depends on hardware, document the measurement environment in the test module doc (CPU, disk, fsync semantics) so R18's reviewer can interpret the numbers.
8. Ensure the corruption tests do not pollute the surrounding workspace `.lattice/` directory; every test uses `tempfile::TempDir`.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Test length ≤30 lines per test; factor setup into shared fixtures in a `tests_common.rs` if repetition appears.
- One test per behavior, named for the behavior (`test_corrupted_payload_returns_typed_error`, not `test_corruption_1`).
- No silent error handling — every `Result` in test code is asserted or propagated with `?` from `#[test] fn x() -> Result<_, _>`.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: `tempfile::TempDir` per test; no shared state between tests.
- Use `tracing_subscriber::fmt::try_init()` at the top of budget tests so failures include capture/storage spans.
