## Goal

This review certifies that Phase 5 — Working Memory — is complete, spec-faithful, and ships the excluded-context auditability that makes working memory trustworthy. The reviewer reads every file produced by T34–T37, runs the verification commands, and writes a structured findings report under `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R38-working-memory.md`. ## Steps

1. Read spec §5. Working Memory, §Phase 5: Working Memory, and the relevant lines of §3. Event Log in full.
2. Run every verification command from T34–T37 in sequence and record pass/fail with output excerpts in the review's `## Findings` section.
3. Audit field coverage: open `WorkingMemoryState` and confirm every one of the eleven spec-named fields is present with the correct nullability and type; flag any field that was renamed or merged.
4. Audit operation coverage: confirm each of the eight required operations exists as a callable, has a test in `operations_tests.rs`, honors the documented contract (idempotency, pin protection, no-op handling, etc.), and emits the appropriate event via T36's hook.
5. Audit excluded-context auditability — the heart of this review:
   - Confirm `ExcludedMemory.exclusion_reason` is non-optional and that every drop/skip path across T35 operations writes a populated reason (sample at least one entry from each of `filter`, `evict`, `compress`).
   - Run the MCP `inspect_working_memory` tool against a synthetic state with mixed include/exclude entries; confirm `include_excluded=true` returns the excluded entries with reasons; confirm `include_excluded=false` does not silently leak them in a separate field.
   - Confirm event hooks emit `MemoryRetrieved` / `MemoryExpanded` events whose payloads carry the included and excluded identity diffs with reasons. Sample at least three event payloads from the test capture.
6. Audit checkpoint integrity: confirm `working_memory_checkpoints` schema has the documented columns and indexes; confirm save/load round-trip is byte-identical via canonical-JSON SHA-256; confirm version mismatch is rejected.
7. Audit MCP surface compliance with spec §9: tool registration appears in `tools/list`; response supports compact and full modes; an `expansion_handle` is included; budget controls are respected.
8. Audit coding-standard compliance across all produced files: file ≤800 lines, function ≤50 lines, nesting ≤3, no TODOs/FIXMEs/commented-out code/unjustified `#[allow(...)]`, single source of truth (no parallel state loader, no parallel event writer, no fixtures duplicated with T32).
9. Cross-check Phase 4 forward-compatibility actually held: confirm `RetrievalBundle` and `BundleResult` are embedded under `selected_memories` and `excluded_memories.result` unchanged from the Phase 4 schema; if a field was added or renamed, flag it as a Phase 4 rework requirement.
10. Write the findings report under `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R38-working-memory.md` with the required headings; assign a verdict; list follow-ups (if any) as actionable items addressed to specific subsequent tasks.
