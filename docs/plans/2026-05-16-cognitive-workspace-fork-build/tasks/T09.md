## Goal

This task delivers the full Phase 1 test matrix that the spec enumerates and the hot-path budget evidence that R10 requires. Spec §Phase 1 explicitly lists "tests for duplicate symbol names, renamed files, moved sections, and branch changes" and the DoD states "identity resolution adds no more than 2ms P99 to hot-path tool calls". This task creates two test files: `resolver_tests.rs` (correctness matrix) and `budget_tests.rs` (P99 measurement under an `#[ignore]` gate so a normal `cargo test` is fast and the slow budget tests run on the review pass).

## Steps

1. Create `daemon/crates/lattice-core/src/identity/resolver_tests.rs` covering the spec test matrix. One test per behavior:
   - `test_resolve_path_unique_returns_fileid`
   - `test_resolve_path_after_file_rename_returns_new_id`
   - `test_resolve_path_after_file_rename_legacy_name_returns_via_compat_shim`
   - `test_resolve_symbol_unique_returns_symbolid`
   - `test_resolve_symbol_duplicate_name_returns_ambiguous_with_disambiguation_hint`
   - `test_resolve_section_after_heading_rename_returns_new_id`
   - `test_resolve_section_after_section_move_returns_new_id`
   - `test_resolve_symbol_on_different_branch_returns_branch_scoped_id`
   - `test_resolve_event_ref_round_trips_through_encoding`
   - `test_resolve_legacy_symbol_name_routes_via_default_workspace`
2. Each test constructs a minimal in-memory or tempdir fixture using the existing parser to populate a tiny graph; assertions verify the exact `ResolveOutcome` variant and the disambiguation hint content.
3. Add a `helpers` submodule (inline) with a fixture builder that other identity tests can reuse — single source of truth for fixture construction.
4. Create `daemon/crates/lattice-core/src/identity/budget_tests.rs` with the P99 measurement. Each budget test is marked `#[ignore]` so a default `cargo test` stays fast and the review runs them with `-- --include-ignored`.
   - `test_resolve_symbol_p99_within_2ms_budget` — runs 10,000 lookups, computes p99, asserts ≤2ms.
   - `test_resolve_path_p99_within_2ms_budget`
   - `test_resolve_section_p99_within_2ms_budget`
   - `test_resolver_does_not_regress_baseline_workflow_p99` — exercises the resolver through the same hot path as `prepare_change` and asserts the delta vs. `baseline_metrics.json` is ≤2ms.
5. Each budget test loads `baseline_metrics.json` from the fixed path, computes the new p99, and asserts the delta with a clear failure message naming the baseline number and the observed number.
6. Add module declarations in `daemon/crates/lattice-core/src/identity/mod.rs`: `#[cfg(test)] mod resolver_tests;` and `#[cfg(test)] mod budget_tests;`.
7. Run `cd daemon && cargo test -p lattice-core --lib identity::resolver_tests` (fast tests) and `cd daemon && cargo test -p lattice-core --lib identity::budget_tests -- --include-ignored` (budget tests) to confirm green.
