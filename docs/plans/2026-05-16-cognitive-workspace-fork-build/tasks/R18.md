## Purpose

This review certifies that the Phase 2 event log substrate meets every spec invariant before Phase 3 (memory graph) begins. It confirms: all 20 event kinds are modeled and emitted by the right tool sites; storage is append-only and replayable; payload spillover, hashing, and content-addressed dedupe work end-to-end; reader queries are bounded and scope-safe; compaction is daemon-managed with a versioned, independently-readable snapshot format; the P99 ≤5ms hot-path budget is met with quantitative evidence. The review verdict gates Phase 3 — a failed review here means Phase 3 cannot start because its memory-provenance depends on a trustworthy event log.

## Review procedure

1. Confirm `EventKind` defines all 20 spec variants in order with canonical wire names and typed payload structs.
2. Confirm `EventEnvelope` carries every spec field (workspace id, branch, session id, task id, actor, timestamp, stable references via Phase 1 identity types, payload hash, compact summary, optional spillover location).
3. Confirm the `events` table has append-only triggers that reject UPDATE and DELETE at the SQLite engine level, with the sanctioned compaction truncate path documented and gated.
4. Confirm indexes exist for task, session, workspace+branch, and kind+ts scopes (read `schema.sql` and verify `PRAGMA index_list` expectations in `store_tests.rs`).
5. Confirm `EventWriter` enforces workspace scoping, hashes payloads with deterministic canonical JSON, deduplicates payloads by hash, and supports both Sync and Batched flush policies.
6. Confirm `EventReader` requires a scope (task / session / workspace+branch), enforces a default + hard-ceiling `limit`, validates payload hash on read, and exposes a streaming variant for replay.
7. Confirm `event_capture.rs` instruments every currently dispatched workflow tool (`prepare_change`, `plan_edit`, `get_context_capsule`, `expand_context`, `get_working_set_context`, `trace_scenario`, `summarize_subsystem`, `impact_from_diff`, `diagnose_failure`, `record_workflow_outcome`, `save_observation`, and others) and that error paths still emit `ToolResult(Error)` without swallowing the JSON-RPC error.
8. Confirm snapshot/compaction is daemon-scheduled (background task), the snapshot format is versioned with an independently-readable header, `Bootstrap::load` dispatches on `format_version`, and the procedure is documented in `docs/architecture/2026-05-16-event-log-compaction.md`.
9. Run the verification commands from tasks.json for T11–T17 from the repo root; capture the JSON output of the budget tests for the P99 evidence section.
10. Audit for coding-standard regressions: file lengths, function lengths, nested-error swallowing, raw-SQL string interpolation, `TODO`/`FIXME`, missing tracing on hot paths.
