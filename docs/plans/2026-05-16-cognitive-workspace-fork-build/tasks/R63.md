## Goal

This task delivers the Phase 8 backend review. It asserts that the redesigned workflow tools (T56, T57), the new memory tools (T58, T59, T60), the audited tool surface (T61), and the integrated outcome recorder + composition tests (T62) together satisfy spec §Phase 8 deliverables and definition of done, with no deferred scope and a tool surface that honors spec §MCP Surface "Tool surface discipline." Without this review, Phase 9 metrics work proceeds against an unvalidated workflow surface and any spec gap discovered later requires reopening Phase 8.

## Spec excerpts that drive this task

> "Phase 8 Deliverables: redesigned versions of context, change planning, scenario tracing, failure diagnosis, docs retrieval, test selection, impact analysis, and playbook generation; workflow composition over graph, event, memory, and working-memory substrates; one-call edit-planning bundles with code, docs, tests, memory, risks, and verification commands; workflow outcome recording integrated by default."

> "Definition of done: common coding tasks require fewer manual discovery calls; workflows produce enough context to implement and verify changes without broad file dumping."

> "Tool surface discipline: ten new memory tools is a meaningful cognitive load for clients … The goal is the smallest surface that covers all assistant workflows. Consolidate before stabilizing the MCP contract." (spec §MCP Surface)

## Steps

1. Read spec §Phase 8 and §MCP Surface in full. Quote the definition-of-done paragraph verbatim at the top of the review.
2. Under `## Spec alignment`, walk every Phase 8 deliverable and cite the implementing files from T56–T62. Flag any deliverable that is missing, partial, or shimmed without a removal deadline.
3. Under `## Coding-standard alignment`, run a per-file check across `daemon/crates/lattice-daemon/src/rpc/workflow_v2/` and `daemon/crates/lattice-daemon/src/rpc/memory_v2/`: file length ≤800 lines, function length ≤50 lines, nesting ≤3, cyclomatic ≤10, schema parity (every public type derives serde), no `TODO`/`FIXME`/commented-out code, no unjustified `#[allow(...)]`, observability spans present. Record each violation with file:line.
4. Under `## Tool-surface size`, list the final shipped tool count (by name) and confirm it matches `docs/architecture/2026-05-16-mcp-tool-reference.md` exactly. Confirm every collapse decision from T61 is implemented in the actual code (e.g. `propose_memory_evolution(action=...)` and `verify_explain_memory(mode=...)` exist and the deprecation shims forward correctly). Flag any tool present in code but missing from the reference, or vice versa.
5. Under `## Findings`, summarize spec gaps, coding-standard violations, surface-size mismatches, hot-path budget regressions (T56 budget assertion, T62 recorder budget), shim policy gaps, and observability gaps. Each finding cites the file:line and the spec or standard it violates.
6. Run `cd daemon && cargo build --release` and `cd daemon && cargo test -p lattice-daemon --lib rpc::workflow_v2 rpc::memory_v2` and record the result in the review.
7. Under `## Verdict`, state `pass` or `fail` with a one-paragraph justification. If `fail`, name the specific tasks that must be reopened.
8. Save the review at `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R63-workflow-engine-v2.md` with the mandatory headings checked by verification commands.
