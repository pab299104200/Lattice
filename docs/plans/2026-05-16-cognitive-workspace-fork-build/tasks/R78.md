## Purpose

This review certifies that the Phase 10 human review UI ships compliant with the shared UI specification, the Lattice coding standard, the spec's mandatory operator view set, and the i18n discipline that all user-facing strings live in a single catalog. It is the gate that R79 (contract gate) and R88 (definition-of-done gate) depend on: a frontend that bypasses `<dialog>`, swallows errors, or inlines English literals would force later phases into rework. Passing this review means the review surface is enterprise-grade on day one per the execution philosophy in `/home/pete/.claude/CLAUDE.md`.

## Review procedure

1. Open every file produced by T71–T77 and confirm the eleven operator views from spec §10 are all reachable from `ReviewPanelProvider`: memory inbox, proposed promotions, proposed contradictions, stale memory list, memory evidence view, event trace view, retrieval explanation view, usefulness metrics, workspace graph health, indexing health, consolidation queue. (Usefulness metrics may live in the existing sidebar from `sidebar.ts` if R70 confirmed that surface; either way the link must be reachable.)
2. Grep every `.ts` file under `extension/src/review/` for `window.confirm(`, `window.prompt(`, `window.alert(` — every hit is a blocker per `ui-specification.md` §7. Grep for `<dialog` to confirm the modals from T73 and T75 use native `<dialog>` elements.
3. Grep every `.ts` file under `extension/src/review/` for inline English literals in JSX-equivalent strings: look for quoted strings inside webview HTML template literals that are not wrapped in `i18n.t(...)`. Any hit is a blocker per `ui-specification.md` §14.
4. Open `extension/src/review/i18n/en.json` and confirm namespaces exist for: panel, statusBadge, memoryInbox, promotionQueue, contradictionQueue, proposalDialog, staleView, evidenceInspector, eventTraceView, retrievalExplanationView, consolidationQueueView, indexingHealthView, workspaceGraphHealthView. Spot-check that every column header, action label, empty state, and error state from the eleven views has a corresponding key.
5. Open every mutation handler (accept/reject in `ProposalDialog`, re-verify in `staleView`/`evidenceInspector`, retry in `consolidationQueueView`, recompute in `workspaceGraphHealthView`) and confirm each is wrapped in `try/catch` with `vscode.window.showErrorMessage(err.message)` plus an inline error state. Silent `.catch(() => {})` or bare `await` without surrounding handler is a blocker per `ui-specification.md` §8.5 and `coding.md` §Error handling.
6. Confirm `StatusBadge.ts` covers all eight verification statuses from spec §8 (`verified`, `unverified`, `in_review`, `stale`, `contradicted`, `superseded`, `expired`, `invalidated`) and every additional badge family (proposal status, job status, decision badge in retrieval explanation). Confirm the file is the only place `verification-status → color/label` mapping lives.
7. Open every table (memory inbox, promotion queue, contradiction queue, stale view, event trace, candidate table in retrieval explanation, consolidation queue, per-family counts in graph health) and confirm sortable columns use the `SortableHeader` + `useTableSort` equivalents exposed by T71 (per `ui-specification.md` §6.2). Confirm pagination is present on every list per `ui-specification.md` §6.1.
8. Open every interactive surface and confirm it renders loading, empty, and error states explicitly (per `ui-specification.md` §8.2, §8.3, §8.5).
9. Grep for `prompt(`, raw `<select>`, and `type="number"` ID inputs — any hit for ID-bearing fields is a blocker. Confirm filter pickers use `vscode.window.showQuickPick`.
10. Run `wc -l` on every file produced by T71–T77 and confirm no file exceeds 800 lines per `coding.md`.
11. Grep all files for `TODO`, `FIXME`, `XXX`, commented-out code, `@ts-ignore`, `@ts-expect-error` without justification — each hit is a blocker per `coding.md` §No broken windows.
12. Run `cd extension && npm install && npm run compile && npm run lint && npm test` and confirm everything passes.
13. Cross-check that the smoke tests from T77 cover every subview from T72–T76 (activation, view registration, mount, empty data, bridge error).

## Required sections in the review output file

The reviewer writes to `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R78-frontend.md` with these mandatory headings (each must contain real findings, not "n/a"):

- `## Spec alignment` — phase-by-phase coverage matrix for spec §10: one row per required operator view (eleven views), evidence column citing the file/function that delivers the view, status PASS / PASS-WITH-CAVEATS / BLOCK.
- `## Coding-standard alignment` — line-by-line audit vs. `coding.md` hard limits: file lengths (`wc -l` table for every Phase 10 file), function-length grep, forbidden-token grep (`TODO`, `FIXME`, `XXX`, commented-out code, unjustified suppressions), error-handling audit (every mutation `try/catch` confirmed), single-source-of-truth audit (status-badge mapping in one place, i18n catalog as single source).
- `## UI-specification compliance` — walk every section of `ui-specification.md` that applies to the review UI in order. Each subsection states the rule, lists the artifacts checked, and the verdict:
  - §3 Accessibility baseline — focus management, keyboard, ARIA, target size, focus rings, live regions on status badges.
  - §6 Lists & tables — pagination present on every list; sortable headers via `SortableHeader` + `useTableSort` equivalents; column standards.
  - §7 Modals & dialogs — every modal native `<dialog>`; no `window.confirm/prompt/alert`; typed-confirm on high-scope destructive actions in `ProposalDialog`.
  - §8 State management — loading, empty, error states on every surface; every mutation has `try/catch` + `vscode.window.showErrorMessage`; error message style obeys Nielsen #9.
  - §11 Visual standards — status badges use the single shared component; semantic color tokens, not hard-coded colors.
  - §12 Data display — dates via `Intl.DateTimeFormat`; truncation on long content.
  - §14 Internationalization — all user-facing strings via `i18n.t(...)`; no inline literals; ICU placeholders on interpolated strings; no string concatenation for user text.
  - §16 Telemetry-friendly markup — `data-testid` on every interactive element; format `data-testid="review-<view>-<action>"`.
- `## i18n coverage` — table of every user-facing string the review UI emits, with the i18n key and the namespace; flag any inline literal that escaped catalog wrapping as a blocker.
- `## Findings` — issues found, severity (`blocker`, `major`, `minor`), suggested follow-up tasks. Follow-up tasks must be opened in this build (do not defer outside).
- `## Verdict` — `PASS`, `PASS-WITH-FOLLOWUP-TASK-Txx`, or `BLOCK` (with named blockers).
