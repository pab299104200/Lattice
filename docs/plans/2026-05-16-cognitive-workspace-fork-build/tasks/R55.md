## Goal

This task is the cross-layer contract gate between the Memory Graph (R25, Phase 3), the Retrieval Engine (R33, Phase 4), and the Verification Engine (R54, Phase 7). It proves that the three subsystems agree on three contract surfaces — `VerificationStatus` round-trips losslessly between memory and verification; `ScopeFilter` reaches every retrieval path; and `BundleProducer` / `SurfacedBundle` (T52) is the single way retrieval surfaces memory results — and that none of the three Phase 8 workflow tools can ship until the contracts hold. The review ships a new contract test file under `daemon/crates/lattice-core/src/contract_tests/` that exercises all three round-trips end-to-end against the real subsystems.

## Spec excerpts that drive this task

> §Non-Negotiable Product Properties: "Every retrieved memory has an inclusion reason. Every stale or contradicted memory is surfaced as such, not hidden behind recency."

> §Verification Engine outputs: `verified`, `unverified`, `in_review`, `stale`, `contradicted`, `superseded`, `expired`, `invalidated`.

> §Risks — Scope Leakage: "scope-aware queries, enforced filters in store APIs, and negative tests."

> §Retrieval Engine: "Ranking signals: ... verification status; freshness; scope; ... contradiction/supersession state ..."

## Steps

1. Read spec §Memory Graph, §Retrieval Engine, §Verification Engine, and §Non-Negotiable Product Properties in full. Copy the relevant bullets into the top-of-file doc comment on `contract_tests/memory_verification_retrieval.rs`.
2. Identify the three contract surfaces explicitly:
   - **VerificationStatus round-trip:** every `VerificationStatus` value persisted by the verifier (T48–T51) deserializes losslessly from `memories.verification_status` and matches the same enum variant in retrieval's ranker (Phase 4).
   - **ScopeFilter round-trip:** every retrieval entry point requires a `ScopeFilter` and applies it through `MemoryStore::list_memories(filter, …)` — no public retrieval API may accept a request without a filter.
   - **SurfacedBundle round-trip:** every retrieval result that touches durable memory passes through `SurfacingPipeline::partition` (T52); no caller composes a trusted/advisory split independently.
3. Create `daemon/crates/lattice-core/src/contract_tests/` (and `mod.rs`) if absent, registered under `#[cfg(test)]` in `lib.rs`.
4. Author `contract_tests/memory_verification_retrieval.rs` with a fixture harness seeding the full Phase 3 + Phase 4 + Phase 7 stack against a temp SQLite store. The fixture seeds memories spanning every `VerificationStatus`, every scope, and a mix of evidence kinds (file / symbol / doc / test) so contract checks have material to assert on.
5. Write `test_verification_status_round_trip_memory_to_retrieval`: persist a memory in each of the eight `VerificationStatus` variants, run a retrieval query, assert each memory's status in the retrieval result equals the persisted value (no silent state mapping).
6. Write `test_scope_filter_round_trip_for_all_scope_kinds`: for each scope (session / branch / repo / organization), construct a non-matching `ScopeFilter`, call the retrieval API, assert zero leaked rows and a `MemoryScopeFiltered` event per attempt.
7. Write `test_stale_label_round_trip_retrieval_to_surfaced_bundle`: seed `Stale`, `Contradicted`, `Superseded`, `Expired`, `Invalidated` memories, run the retrieval pipeline, assert none appear in `SurfacedBundle.trusted` and each appears in `SurfacedBundle.advisory` with the matching `BundleSection` and a non-empty `label_reason`.
8. Write `test_retrieval_api_requires_scope_filter_argument`: a compile-time test (using `compile_fail` doctests or a `trybuild` fixture) that confirms the public retrieval entry point fails to compile without a `ScopeFilter`. If `trybuild` is unavailable in this crate, fall back to a runtime test asserting every public retrieval function in `query::engine` has a `ScopeFilter`-typed parameter (via reflection / a manually maintained list audited in this test).
9. Run `cd daemon && cargo test -p lattice-core --lib contract_tests::memory_verification_retrieval` and capture the results in the review.
10. Write the review at `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R55-contract-memory-verification-retrieval.md` with the mandatory headings: `## Contract surfaces`, `## Round-trip evidence`, `## Stale-label round-trip`, `## Scope-filter round-trip`, `## Findings`, `## Verdict`. `## Contract surfaces` enumerates the three contract surfaces and the code paths that implement them. `## Round-trip evidence`, `## Stale-label round-trip`, and `## Scope-filter round-trip` each cite the matching contract test and its assertions. `## Verdict` states `pass` or `fail` with one-paragraph justification.
