# T08 — Phase 1 — Identity serialization in MCP payloads + legacy name compatibility shim

**Phase:** 1
**Type:** backend
**Model class:** balanced
**Depends on:** T07
**Spec anchor:** [§Phase 1: Unified Identity Model](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-1-unified-identity-model)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task wires the new `Identity` types into the MCP JSON-RPC surface so every workflow tool response carries stable identities the client can expand later, while preserving legacy name-based fields so existing clients continue to function. Spec §Phase 1 deliverables include "explicit identity serialization in MCP payloads" and "compatibility support for legacy name-based references". The compatibility shim is the binding mechanism by which T02's MCP compatibility policy is honored for Phase 1.

## Spec excerpts that drive this task

> "Phase 1 Deliverables: ... explicit identity serialization in MCP payloads; compatibility support for legacy name-based references."

> "Definition of done: every workflow output can be expanded through a stable identity."

## Steps

1. Create `daemon/crates/lattice-core/src/identity/serialization.rs` with serde helpers that emit the compact wire form defined in T06 `encoding.rs` and accept either compact form or structured object form on deserialize.
2. Define a `pub struct IdentityPayload` containing both the compact `id` string and a structured `fields` object, plus an optional `legacy_name` field for backward compatibility. Serialization round-trips through both forms.
3. Add `pub fn serialize_outcome<T: Into<Identity>>(outcome: ResolveOutcome<T>) -> IdentityPayloadOrAmbiguity` that converts the resolver outcome to the wire shape, preserving `Ambiguous` as a structured diagnostic instead of an arbitrary pick.
4. Create `daemon/crates/lattice-daemon/src/rpc/identity_payload.rs` with the MCP wiring: a wrapper that decorates every workflow tool response (or its top-level pivot list) with `IdentityPayload` values and preserves the legacy name field listed in the T02 compatibility policy for each tool.
5. Wire one representative tool (`get_context_capsule` or `prepare_change`) end-to-end through the new serialization wrapper as a proof of integration; full Phase 8 redesign of every tool is owned later, but Phase 1 must demonstrate the integration path works without regressing existing clients.
6. Add tests under `daemon/crates/lattice-core/src/identity/serialization.rs` (`#[cfg(test)] mod tests`) covering: compact-form round-trip, structured-form acceptance, legacy-name preservation, ambiguity payload shape.
7. Add tests under `daemon/crates/lattice-daemon/src/rpc/identity_payload.rs` covering: a full tool response that includes both identity payloads and legacy fields, and a response where the resolver returned `Ambiguous` (the response must surface the ambiguity diagnostic rather than silently picking).
8. Update the workflow tool that was wired in step 5 to emit identity payloads alongside its prior fields; document the change in `docs/architecture/2026-05-16-mcp-compatibility-policy.md` under the per-tool classification.
9. Run `cd daemon && cargo build --release`, `cd daemon && cargo test --workspace -- identity::serialization`, and `cd daemon && cargo test --workspace -- rpc::identity_payload` to confirm green.
