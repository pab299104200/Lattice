# T16 — Phase 2 — Event log compaction snapshot + bootstrap-from-snapshot

**Phase:** 2
**Type:** backend
**Model class:** advanced
**Depends on:** T12, T13, T14
**Spec anchor:** [§Storage Design](../../2026-05-16-cognitive-workspace-fork-plan.md#storage-design)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

The spec requires append-only event storage with compaction: at configurable intervals, write a full-state snapshot of graph and memory to a separate file, then truncate the event log to events after the snapshot timestamp. This task implements that snapshot writer, the bootstrap-from-snapshot loader that lets the daemon start without replaying full history, the daemon-managed background scheduler that runs compaction off the hot path, and the architecture doc that records the format version, schedule semantics, and recovery procedure. Snapshots are the only mechanism preventing unbounded event-log growth for long-running repos; without this task, the event log substrate is incomplete.

## Spec excerpts that drive this task

> "Event log compaction: append-only storage will grow unboundedly for long-running repos. The storage design must include a compaction snapshot strategy: at configurable intervals, write a full-state snapshot of graph and memory to a separate file, then truncate the event log to events after the snapshot timestamp."

> "The snapshot format must be versioned and independently readable so the daemon can bootstrap from a snapshot without replaying the full history. Compaction must be a daemon-managed background operation, not a user-initiated manual step."

> "Every background consolidation pass is recoverable, replayable, and observable."

## Steps

1. In `events/snapshot.rs`, define `pub struct Snapshot { format_version: u16, taken_at: DateTime<Utc>, up_to_event_id: EventId, graph_state: GraphSnapshot, memory_state: MemorySnapshot, content_hash: SnapshotHash }`. `format_version` is a `u16` starting at 1 and is the only field whose meaning must never change — bootstrap loaders dispatch on it.
2. Define the snapshot file layout (`.lattice/snapshots/snapshot-<event_id>-<unix_micros>.bin`): a fixed 64-byte header (`magic[8]`, `format_version`, `flags`, `header_len`, `content_offset`, `content_len`, `content_hash[32]`) followed by a `bincode`- or `serde_cbor`-encoded body. The header is independently readable without the body decoder so loaders can refuse incompatible versions before allocating.
3. Implement `Snapshot::write(path, graph, memory, up_to_event_id) -> Result<SnapshotHandle, SnapshotError>` and `Snapshot::read(path) -> Result<Snapshot, SnapshotError>`.
4. In `events/compaction.rs`, define `pub struct Compactor { store: Arc<EventStore>, writer: Arc<EventWriter>, graph: Arc<GraphHandle>, memory: Arc<MemoryHandle>, config: CompactionConfig }` where `CompactionConfig` carries `interval: Duration`, `min_events_since_last`, `snapshot_dir: PathBuf`, `retain_snapshots: usize`.
5. Implement `Compactor::run_once(&self) -> Result<CompactionReport, CompactionError>`:
   1. Acquire a compaction lock so concurrent compactions are impossible.
   2. Snapshot current graph + memory state and the `up_to_event_id` cursor (latest `event_id` at snapshot time).
   3. Write snapshot file atomically (temp-file + rename).
   4. Verify the snapshot reads back cleanly (round-trip check) before truncating anything.
   5. Truncate the event log to rows with `event_id > up_to_event_id` using the sanctioned truncate path from T12 — the trigger remains in place for normal writes.
   6. Emit a `MemoryConsolidated` event (or a dedicated `SnapshotTaken` event added to T11 if the spec list permits — otherwise reuse `MemoryConsolidated` with a tagged summary) so the new log still records that compaction happened.
   7. Rotate old snapshots beyond `retain_snapshots`.
   8. Return a `CompactionReport` with bytes written, events truncated, duration, and snapshot path.
6. Implement `Compactor::spawn_scheduler(self) -> SchedulerHandle` that runs `run_once` on a `tokio::time::interval` (or equivalent) using a dedicated background task — never on the request thread. `SchedulerHandle::shutdown()` lets the daemon stop the loop cleanly.
7. Implement `Bootstrap::load(snapshot_path: &Path, event_store: &EventStore) -> Result<BootstrappedState, BootstrapError>`: read the snapshot header, dispatch on `format_version`, decode the body, then replay events with `event_id > snapshot.up_to_event_id` via `EventReader::stream`. Fail loudly if any post-snapshot event references state not present in the snapshot (`BootstrapError::ReferenceUnresolved`).
8. Define typed errors throughout: `SnapshotError { IoFailed, HeaderUnrecognized { magic }, FormatVersionUnsupported { found, max }, ContentHashMismatch, Serde }`; `CompactionError { LockHeld, SnapshotFailed(SnapshotError), TruncateFailed(EventStoreError), VerifyFailed }`; `BootstrapError { SnapshotMissing, FormatVersionUnsupported, ReferenceUnresolved { event_id, missing_ref } }`.
9. Wire `Compactor::spawn_scheduler` into the daemon lifecycle so it starts on daemon boot and shuts down on signal; this task's wiring is minimal (one call site), with the broader daemon-lifecycle integration covered by existing patterns.
10. In `events/snapshot_tests.rs`, write tests for:
    - snapshot write + read round-trip preserves graph and memory state byte-for-byte.
    - format-version mismatch on read returns `FormatVersionUnsupported` and does not panic.
    - content-hash mismatch returns `ContentHashMismatch`.
    - compaction is idempotent if run twice with no new events.
    - bootstrap from snapshot + tail-events reconstitutes the same state as a full replay.
    - scheduler shutdown cancels an in-progress compaction cleanly without partial truncation.
11. Write `docs/architecture/2026-05-16-event-log-compaction.md` with sections: `## Snapshot format`, `## Compaction schedule`, `## Bootstrap procedure`, `## Recovery from corrupt snapshot`, `## Retention policy`, `## Observability`. The doc is the authoritative reference; cite it from `events/snapshot.rs` and `events/compaction.rs` via Markdown heading references in module docs.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: snapshot body fields match the graph and memory shapes they capture; format-version bump for any field change.
- No silent error handling — every `SnapshotError` / `CompactionError` / `BootstrapError` propagated; the scheduler logs at `error` and continues to the next interval rather than panicking.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: the sanctioned truncate path is a documented exception to the append-only trigger; comment in code and in the architecture doc explains why.
- Use `tracing::info_span!("compaction", interval = ?)`, `tracing::warn!` on retention rotation, `tracing::error!` on `CompactionError`.
