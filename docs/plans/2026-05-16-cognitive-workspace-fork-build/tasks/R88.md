## Purpose

This review walks every section of the shared `definition-of-done-checklist.md` against the whole cognitive-workspace fork and certifies that each applicable item is satisfied or explicitly deferred with reason, owner, and target date per the execution philosophy in `/home/pete/.claude/CLAUDE.md` ("Never defer work you can do now"). ## Review procedure

1. Open `definition-of-done-checklist.md` and walk it section by section against the fork delivery. Each section below is a heading in the output file and a procedure here.
2. **Workflow Completion**: Confirm every primary operator workflow works end to end. For the fork, the primary workflows are: (a) the assistant calling MCP tools to plan and apply a change; (b) the operator reviewing the memory inbox, accepting/rejecting promotions and contradictions, inspecting evidence, and triggering on-demand verification; (c) the operator deploying a new daemon binary via the runbook. Confirm both backend and operator-facing UI are complete for every user-visible workflow. Confirm background jobs (consolidation, verification, compaction) are complete.
3. **Failure Handling**: Confirm validation failures return actionable errors. Confirm permission-denied is not applicable (local-first, no per-user RBAC), but workspace-boundary enforcement is verified by T83. Confirm not-found and conflict states are truthful (e.g. proposal apply on an already-applied proposal returns a clear error per T81). Confirm partial-failure behavior is defined for async paths (consolidation queue, verification jobs). Confirm UI shows loading / empty / success / failure states per R78.
4. **Security, Tenancy, and Audit**: Confirm access control is local-first; workspace scope is enforced per T83. Confirm destructive actions (memory invalidation, high-scope promotion) require explicit operator confirm per T73. Confirm meaningful state-changing actions create event-log records per Phase 2 + Phase 8. Confirm sensitive data (event payloads with file content) is local-only and not exposed externally.
5. **Data Integrity and Workflow Controls**: Confirm invariants are enforced at the storage layer (foreign keys on `memory_links`, `memory_evidence`; constraints on verification status enum; uniqueness on event id). Confirm workflow statuses use explicit transition rules (verification status state machine, proposal state machine). Confirm invalid transitions are blocked and tested (T81 idempotency test).
6. **Observability and Recovery**: Confirm logs and event records provide enough context to debug production failures (T82 recovery tests; T83 workspace-boundary tests emit `security` target events). Confirm critical async paths are idempotent (T81 replay-safe consolidation). Confirm recovery steps exist (T86 recovery playbook). Confirm rollback is defined (T84 migration rollback).
7. **Performance and Scale**: Confirm the design avoids N+1 and broad scans per spec §Non-Negotiable Product Properties (T83 no-broad-fallback test). Confirm pagination / sortable headers are server-side capable for the review UI (R78). Confirm large-repo scale is exercised (T80). Confirm known scale limits are documented (T80 results in `large_repo_results.json`).
8. **Documentation and Operator Readiness**: Confirm architecture documentation updated for every structural change (T02, T03, T16, T85). Confirm functional documentation reflects every behavior change. Confirm manual documentation (operator guide, runbook, recovery playbook) is updated per T85 + T86. Confirm operator-facing warnings (queue at bound, dropped jobs, broken references) are documented per T76 + T86.
9. **Verification Evidence**: Confirm unit, integration, and E2E coverage exists. Confirm test commands were executed and results captured (R87 hardening evidence + R79 contract round-trip evidence). Confirm manual verification was captured for UI-heavy changes (R78).
10. **Explicit Deferrals**: Walk every task brief T01–T86 and every review R05–R87. List every item explicitly deferred with reason, owner, and target date. Per `/home/pete/.claude/CLAUDE.md` execution philosophy, the expected state is an empty list. Any deferral must be justified or rejected back to the build.
