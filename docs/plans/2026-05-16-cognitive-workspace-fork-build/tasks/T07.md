## Goal

This task implements the resolver that turns user-supplied or LLM-supplied references — paths, qualified symbol names, doc headings, test names, event refs — into the stable `Identity` values defined in T06. Spec §Phase 1 names "identity resolver for paths, symbols, headings, tests, and event refs" as a deliverable and binds the resolver to return ambiguity diagnostics rather than arbitrary matches when an input has multiple candidate identities. Without this resolver, every later phase would re-implement name→id lookups inconsistently, and ambiguity would be silently swallowed.

## Steps

1. Create `daemon/crates/lattice-core/src/identity/resolver.rs` with a `pub struct IdentityResolver` that holds references to the graph, storage, and parser indexes needed to answer lookups.
2. Define the resolver public API:
   - `resolve_path(&self, workspace: &WorkspaceId, path: &str) -> Result<FileId, ResolveError>`
   - `resolve_symbol(&self, workspace: &WorkspaceId, qualified_name: &str) -> ResolveOutcome<SymbolId>`
   - `resolve_section(&self, workspace: &WorkspaceId, doc: &DocId, heading: &str) -> ResolveOutcome<SectionId>`
   - `resolve_test(&self, workspace: &WorkspaceId, test_name: &str) -> ResolveOutcome<SymbolId>` (tests are identified as symbols with a `Test` kind)
   - `resolve_event_ref(&self, workspace: &WorkspaceId, ref_str: &str) -> Result<EventId, ResolveError>`
3. Create `daemon/crates/lattice-core/src/identity/ambiguity.rs` with the `ResolveOutcome<T>` enum (`Unique(T)`, `Ambiguous(AmbiguityReport<T>)`, `NotFound(ResolveError)`) and the `AmbiguityReport<T>` struct carrying the list of candidates plus a `disambiguation_hint` describing how the caller can narrow the query (suggest adding parent module, file path, byte offset, etc.).
4. The resolver must never pick arbitrarily when multiple matches exist — return `Ambiguous`. Tests in T09 will assert this on duplicate symbol names.
5. Add a legacy compatibility helper `pub fn resolve_legacy_symbol_name(&self, name: &str) -> ResolveOutcome<SymbolId>` that takes a name without workspace context and routes to the resolver via the default workspace, preserving older MCP payloads.
6. Implement caching: keep a small LRU keyed by `(workspace, query)` so the same resolution within a session does not re-traverse the graph. Cache hits must still preserve ambiguity semantics — a cached `Ambiguous` returns `Ambiguous`.
7. Errors are structured: `ResolveError::WorkspaceNotIndexed`, `ResolveError::Malformed`, `ResolveError::IndexLagBehind { latest_event_id }`. No bare `String` errors.
8. Add module-level docs in both files citing spec §Phase 1.
9. Register the new submodules in `daemon/crates/lattice-core/src/identity/mod.rs` with `pub mod resolver;` and `pub mod ambiguity;`.
10. Write smoke unit tests inline (the full ambiguity / rename / branch-change test matrix is owned by T09): construct a tiny resolver fixture and assert `resolve_path` returns a `FileId`, `resolve_symbol` on a duplicate name returns `Ambiguous`, and `resolve_legacy_symbol_name` falls back correctly.
