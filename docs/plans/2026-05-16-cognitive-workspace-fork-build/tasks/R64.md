# R64 — Contract gate — MCP tool surface schema regression

**Phase:** 8
**Type:** review
**Model class:** advanced
**Depends on:** R63
**Spec anchor:** [§MCP Tool Contract Principles](../../2026-05-16-cognitive-workspace-fork-plan.md#mcp-tool-contract-principles)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`); `AGENTS.md` "Backward-compatibility and contract discipline."

## Goal

This task is the contract gate for the redesigned MCP tool surface. It asserts every shipped tool round-trips request/response through serde without loss, exposes the spec-required render modes (`compact`, `full`, `diagnostic`, `handles`), keeps every deprecation shim from the T02 compatibility policy responding correctly, and surfaces no schema drift between the implementation, the T61 reference doc, and any client expectations. Without this gate, schema drift between the daemon and assistant clients goes undetected until production, violating spec §Non-Negotiable Product Properties "Every public MCP contract is documented and regression-tested."

## Spec excerpts that drive this task

> "Every public MCP contract is documented and regression-tested." (spec §Non-Negotiable Product Properties)

> "Every tool response should support: compact rendering, full structured JSON, context handles, stable expansion targets, budget controls, diagnostic explanations where useful." (spec §MCP Surface)

> "Every assistant-facing tool should return: overview, ranked pivots, relevant context, memory highlights, event episodes where relevant, suggested next expansion, stable handles, risks or uncertainty, compact/full render choice, structured payload." (spec §MCP Tool Contract Principles)

## Steps

1. Read spec §MCP Surface, §MCP Tool Contract Principles, and §Non-Negotiable Product Properties in full. Quote the "Every public MCP contract is documented and regression-tested" sentence verbatim at the top of the review.
2. Implement `daemon/crates/lattice-daemon/src/rpc/mcp_schema_tests.rs` as a comprehensive regression test file covering: (a) every registered tool name matches `2026-05-16-mcp-tool-reference.md` exactly; (b) every tool's request schema round-trips through serde without loss; (c) every tool's response schema round-trips through serde without loss; (d) every tool produces a valid response in each render mode (`compact`, `full`, `diagnostic`) and returns at least one stable expansion handle when the spec requires one; (e) every deprecation shim from the T02 compatibility policy still responds and forwards to its successor; (f) any schema field added in T56–T60 is backward-compatible (additive, optional, with serde defaults).
3. Under `## Schema surfaces`, enumerate every shipped tool name and confirm: registered in `mcp.rs`, listed in the T61 reference, covered by `mcp_schema_tests.rs`. Flag any mismatch.
4. Under `## Render-mode coverage`, build a matrix: rows are tools, columns are `compact`, `full`, `diagnostic`, `handles`. Mark each cell with the tool/test name proving the support. Spec §MCP Surface requires every tool support compact + full + diagnostic + handles; cells without coverage are gate failures.
5. Under `## Backward-compatibility shims`, list every shim required by the T02 compatibility policy (including `apply_memory_evolution → propose_memory_evolution(action="apply")`, `verify_memory → verify_explain_memory(mode="verify")`, `explain_memory → verify_explain_memory(mode="explain")`, plus legacy `prepare_change`/`plan_edit`/`trace_scenario`/`diagnose_failure`/`get_context_capsule`/`get_docs_capsule`/`find_relevant_tests`/`impact_from_diff`/`record_workflow_outcome` shims). For each, cite the regression test that exercises the shim.
6. Under `## Findings`, summarize schema drift, render-mode gaps, shim regressions, backward-compatibility violations, and any divergence between the T61 reference and the implementation. Each finding cites file:line and the spec or policy it violates.
7. Run `cd daemon && cargo test -p lattice-daemon --lib rpc::mcp_schema_tests` and record the result in the review.
8. Under `## Verdict`, state `pass` or `fail` with a one-paragraph justification. If `fail`, name the specific tools or shims that must be repaired.
9. Save the review at `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R64-contract-mcp-schema.md` and the new test file at `daemon/crates/lattice-daemon/src/rpc/mcp_schema_tests.rs`.
