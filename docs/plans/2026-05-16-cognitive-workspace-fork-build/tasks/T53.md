**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task ships the cross-module integration suite that proves Phase 7's two non-negotiable invariants end-to-end: (1) stale, contradicted, superseded, expired, or invalidated memory NEVER appears in the trusted section of any bundle the system produces, and (2) scope-leak attempts (cross-branch, cross-workspace, cross-organization) are blocked at the store boundary, return zero leaked rows, and emit the audit event. Unit tests in T48–T52 cover each module in isolation; this task wires them together so the spec's stale-surfacing and scope-leakage risk controls are demonstrably enforced in the running system, not just in theory.

## Spec excerpts that drive this task

> §Non-Negotiable Product Properties: "Every stale or contradicted memory is surfaced as such, not hidden behind recency."

> §Risks — Stale Memory Leakage: "Control: freshness indexes, graph-change-triggered verification, stale labels in all memory surfaces, and tests that stale memory cannot rank as trusted."

> §Risks — Scope Leakage: "Control: scope-aware queries, enforced filters in store APIs, and negative tests."

> Phase 7 DoD: "stale or contradicted memory cannot appear as normal trusted guidance".

## Steps

1. Read spec §Phase 7 DoD + §Non-Negotiable Product Properties stale-surfacing bullet + §Risks Stale Memory Leakage + §Risks Scope Leakage. Copy all four into the top-of-file doc comment on `integration_tests.rs`.
2. Build a `VerificationHarness` (top of file or sibling support module): seeds a temp SQLite store with the Phase 1/2/3/6/7 schemas, registers the indexer hook for incremental verification, sets up a fake LLM driver only where consolidation interplay is required, exposes a `bundle_through_surfacing` helper that takes raw memories and runs them through `SurfacingPipeline::partition` to assert on the trusted/advisory split.
3. Write `test_stale_memory_never_appears_in_trusted_bundle` (covers T48/T49/T52): seed a memory whose evidence cites file `F`, modify the span content in `F`, run incremental verification, then call `bundle_through_surfacing(retrieved_memories)`; assert the memory is in `advisory` with `BundleSection::Stale` and NOT in `trusted`.
4. Write `test_contradicted_memory_never_appears_in_trusted_bundle` (covers T48 + Phase 6 contradiction): seed two contradicting memories, trigger the Phase 6 contradiction job, apply the proposal flipping one to `contradicted`, then bundle and assert it is in `advisory` with `BundleSection::Contradicted`.
5. Write `test_expired_memory_never_appears_in_trusted_bundle` (covers T51): seed a memory with `expires_at = now - 1s`, run `ExpiryScanner::scan`, then bundle and assert the memory is in `advisory` with `BundleSection::Expired`.
6. Write `test_invalidated_memory_never_appears_in_trusted_bundle` (covers T48): seed a memory whose evidence cites file `F`, delete `F`, run incremental verification, bundle, assert `BundleSection::Invalidated`.
7. Write `test_scope_leak_blocked_at_store_boundary_for_all_scopes` (covers T50): seed memories of each scope (session / branch / repo / organization), call `list_memories` with a non-matching `ScopeFilter` for each scope, assert zero leaked rows AND a `MemoryScopeFiltered` event per leak attempt.
8. Write `test_ranker_excludes_non_verified_from_top_n` (covers T52 hard precondition): seed five memories, four `Stale` and one `Verified`, run the ranker with `top_n = 5`, assert only the `Verified` memory appears in the trusted list regardless of its raw score.
9. Write `test_incremental_verification_narrows_to_changed_files_only` (covers T51): seed 100 memories citing 100 distinct files, modify only file `F_07`, trigger `IncrementalVerifier::on_graph_delta`, assert exactly one memory was re-verified (use the counting test seam from T51).
10. Write `test_verifier_emits_explainable_label_reason_for_every_non_verified_state` (covers T48/T49/T50/T51/T52): produce one memory per non-verified state, bundle, assert each `LabeledMemory.label_reason` is non-empty AND mentions the verifier's structured reason field (file id, span byte range, scope mismatch, or expiry timestamp).
11. Wire the suite via `mod integration_tests;` in `verification/mod.rs` under `#[cfg(test)]` (match the Phase 6 convention from T46).
