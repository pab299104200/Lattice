# T67 — Phase 9 — get_memory_metrics + retrieval relevance surfaces wired through MCP

**Phase:** 9
**Type:** backend
**Model class:** balanced
**Depends on:** T65
**Spec anchor:** [§Phase 9: Metrics And Evaluation](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-9-metrics-and-evaluation)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task wires the T65 metrics module through the MCP surface so the `get_memory_metrics` tool from T60 returns the full canonical signal set rather than the fallback session_metrics view, and adds per-call retrieval relevance surfaces (inclusion reasons, scoring breakdowns) into the existing workflow tool responses. Spec §Phase 9 Deliverables names "retrieval relevance metrics" as binding, and spec §Phase 4 Definition of Done requires "workflow tools return memory with inclusion reasons and stable expansion handles … irrelevant memory rate is measured and regressed." Without this task, the metrics module ships but no MCP client can read it and no per-call relevance signal is exposed.

## Spec excerpts that drive this task

> "Phase 9 Deliverables: retrieval relevance metrics; memory usefulness metrics; context token efficiency metrics; stale/contradicted memory surfacing metrics."

> "Workflow tools return memory with inclusion reasons and stable expansion handles … irrelevant memory rate is measured and regressed." (spec §Phase 4 DoD)

> "The ranker should expose scores and reasons in diagnostic mode. Compact mode should include only enough explanation for an assistant to trust the result." (spec §Retrieval Engine)

## Steps

1. Read spec §Phase 9, §Retrieval Engine, and §Phase 4 DoD in full.
2. Implement `daemon/crates/lattice-daemon/src/rpc/metrics_surface.rs` as the MCP-facing facade over the T65 `MetricsCollector`. It exposes: (a) `MetricsSurface::collect(scope, signals)` calling the T65 collector and returning `Vec<MetricValue>`; (b) `MetricsSurface::collect_for_call(task_id, tool_name)` returning per-call relevance: per-pivot inclusion score breakdown (graph proximity, semantic similarity, freshness, scope, verification, evidence strength, past usefulness — per spec §Retrieval Engine "Ranking signals"), per-memory inclusion reason, excluded high-scoring candidates with rejection reasons; (c) `MetricsSurface::summarize_for_compact_mode(...)` returning a one-line digest suitable for compact tool responses.
3. Wire `metrics_surface.rs` into `memory_v2/get_memory_metrics.rs` so the tool reads from the T65 collector through this facade rather than the fallback `session_metrics`. The fallback path remains as an explicit `source: SessionMetrics` value when the collector returns `None` for a given signal — never fabricate a value.
4. Extend the T56/T57 workflow tools' responses to attach per-call relevance via `MetricsSurface::collect_for_call`. In `compact` render mode each `MemoryHighlight` and `Pivot` carries the summarized one-line digest; in `full` / `diagnostic` mode each carries the full score breakdown. Spec §Retrieval Engine: "The ranker should expose scores and reasons in diagnostic mode."
5. Add a stable expansion handle (`relevance_detail_handle`) on every `MemoryHighlight` and `Pivot` so `expand_context` can fetch the full diagnostic breakdown without re-running the workflow.
6. Workspace boundary + scope-leak protections: every `MetricsSurface::collect_for_call` query honors workspace and scope filters, matching the discipline established in T58–T60.
7. In `metrics_surface_tests.rs`, write tests that: (a) round-trip the surface's request/response through serde; (b) assert the surface returns every T65 `MetricSignal` variant; (c) assert it returns `null` with a reason when no data is available, never a fabricated value; (d) assert per-call relevance includes every ranking-signal column from spec §Retrieval Engine; (e) assert compact mode digests are bounded in size; (f) assert the diagnostic expansion handle dereferences to the full breakdown; (g) assert workspace boundary and scope filters reject cross-scope queries with a typed error.
