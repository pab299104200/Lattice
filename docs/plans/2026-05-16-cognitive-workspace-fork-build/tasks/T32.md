## Goal

This task closes Phase 4 with the benchmark suite, golden anchor fixtures, and ranking regression tests required by spec §Phase 4 deliverables ("benchmark suite for realistic assistant tasks") and §Phase 4 Definition of Done ("irrelevant memory rate is measured and regressed"). The benchmark must measure end-to-end retrieval against a fixed set of representative tasks, the golden anchor tests must pin the anchor-resolution behaviour against a curated corpus, and ranking regression tests must guard against silent reordering of the ranked output as future signals are tuned. Metrics are written to a baseline JSON file under `docs/plans/.../baselines/` so future runs can diff against it without re-reading the test fixtures.

## Steps

1. Re-read spec §Phase 4 deliverables and Definition of Done, and §Phase 9 metrics list, to fix the metrics the benchmark must emit: top-K precision, top-K recall, irrelevant-memory rate, mean rank of golden result, P50/P95 retrieval latency, candidates per source, dedupe rate, truncation rate.
2. Curate a golden anchor corpus in `daemon/crates/lattice-core/src/retrieval_v1/golden_tests.rs` covering each anchor type (path, symbol, error string, command, API name, config key) with at least three task statements per type, the expected resolved identities, and the expected top-1 result identity. The corpus is in code (not external fixtures) so the test is hermetic.
3. Implement `daemon/crates/lattice-core/src/retrieval_v1/benchmark.rs` as an `#[ignore]`d test that builds a synthetic workspace (small fixture graph + memories + events), runs the full retrieval pipeline against the golden corpus, computes the metrics list above, asserts against pinned thresholds documented inline, and writes the metric snapshot to `docs/plans/2026-05-16-cognitive-workspace-fork-build/baselines/retrieval_v1_metrics.json`. The `#[ignore]` lets `cargo test` stay fast while CI runs `cargo test -- --include-ignored`.
4. Implement ranking regression tests in `golden_tests.rs`: for every golden task, assert that the top-1 result is the expected identity, that the second result is not a stale memory unless the task expects one, and that the inclusion reason for the top result mentions the dominant signal (e.g. an exact-symbol-match task surfaces "exact identifier match" in the reason). Tests are ≤30 lines each.
5. Pin a stale-memory regression: include at least one golden task where a stale memory exists in the fixture and assert that the stale memory ranks below the trusted result, per spec §Stale Memory Leakage control.
6. Pin a budget regression: include at least one golden task with a deliberately-oversized candidate set and assert that truncation flips `BudgetReport::truncated`, that pinned results survive truncation, and that the bundle still ships within the documented token cap.
7. Write `retrieval_v1_metrics.json` schema documentation as a doc comment at the top of `benchmark.rs`: every field, its meaning, its threshold, and the rule for tightening it.
8. Add a CLI hook (small Rust binary entry under the existing benchmark scaffolding, or a `cargo run --example retrieval_v1_metrics`) only if the existing benchmark convention supports it; otherwise the `--include-ignored` test alone satisfies the verification command. Document the convention chosen at the top of `benchmark.rs`.
9. Run all four verification commands locally; fix any clippy warnings before stopping.

## Coding-standard checks

- File length ≤800 lines per file. If the golden corpus grows beyond the cap, split into `golden_tests/` submodules grouped by anchor kind.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10. Each test ≤30 lines per `coding.md` "Tests as documentation".
- Schema parity: `retrieval_v1_metrics.json` field set mirrors the `BenchmarkMetrics` struct in `benchmark.rs` exactly; both are updated in the same commit.
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- Single source of truth: thresholds live in `benchmark.rs` as documented constants; they are not duplicated in `golden_tests.rs`.
- No broken windows: dead imports removed, every test is named for the behaviour it asserts (e.g. `test_exact_symbol_anchor_returns_correct_identity`).
- Doc citation: thresholds cite `## Phase 4: Retrieval V1` (Definition of Done) and `## Phase 9: Metrics And Evaluation` per `/home/pete/cadres/lattice/CLAUDE.md`.
