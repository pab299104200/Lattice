## Goal

This task makes every consolidation job — synchronous, background, manual-review, and LLM-driven — replay-safe and reversible. Spec §Non-Negotiable Product Properties demands "every background consolidation pass is recoverable, replayable, and observable" and spec §Consolidation Engine names `replay mode for rebuilding memory state from the event log` as one of the four consolidation modes. This task adds the replay driver, ensures that every applied proposal preserves prior state so reversal is mechanical, and verifies that replaying the event log reconstructs the same memory state without depending on wall-clock time, RNG order, or driver responses cached from the first run.

## Steps

1. Read spec §Consolidation Engine "Consolidation modes" + §Non-Negotiable Product Properties bullet on replayability. Copy both verbatim into the top-of-file doc comment on `replay.rs`.
2. In `consolidation/replay.rs`, define `pub struct ReplayDriver { event_reader, proposal_store, memory_store, llm_response_cache: HashMap<PromptHash, ResponseBytes> }` and `pub enum ReplayMode { FromGenesis, FromSnapshot { snapshot_id }, FromEventId(EventId) }`.
3. Implement `ReplayDriver::replay(mode) -> ReplayReport`: (a) reset memory state to the snapshot's baseline (or empty if `FromGenesis`), (b) iterate `MemoryConsolidated` / `ConsolidationFailed` events in `event_id` order, (c) for each `MemoryConsolidated`, re-apply `proposed_state` from the embedded payload — do NOT re-call deterministic scanners or LLM drivers; replay is data-replay, not job-replay, (d) verify the resulting memory state hashes match the post-event hash recorded at original apply time (record-and-verify).
4. Implement `ReplayDriver::reverse(proposal_id) -> Result<(), ReverseError>` for proposal reversal: read `prior_state` from `consolidation_proposals`, write it back through the memory store, emit a `MemoryConsolidated` event with `proposed_state = prior_state` and `prior_state = proposed_state` (the reverse delta), flip the proposal's `decision` to `reverted`. Reversal must be atomic: either all writes commit or none. Add a `reverted` variant to `ProposalDecision` (extend the T39 enum) and the matching migration.
5. Add a `replay_safety` invariant test seam: provenance hashes (T43) are the cache key for LLM responses during replay, so replay never depends on a live LLM driver. Add `ReplayDriver::with_cached_responses(provenance_index)` that loads cached responses keyed by `prompt_sha256` from prior runs.
6. Ensure replay is deterministic: forbid wall-clock reads inside replay (`SystemTime::now` calls must come from an injected `Clock` trait the replay driver pins to the original event's timestamp). Forbid RNG inside the consolidation runtime (audit during this task; if any rng was introduced in T41/T42, replace with seeded RNG).
7. Make every applied proposal include `post_apply_state_hash: [u8; 32]` in its `MemoryConsolidated` payload so replay can detect divergence. Update `events::kinds::MemoryConsolidatedPayload` accordingly and bump its serde version handling per Phase 2 conventions.
8. In `consolidation/replay_tests.rs`, write tests that: (a) `replay(FromGenesis)` on a fixture with 50 mixed deterministic + LLM proposals reconstructs the same memory state byte-for-byte (state hash match), (b) reversal of a `Refresh` proposal restores `last_verified_at` exactly, (c) reversal of a `Supersede` proposal flips status back and clears the `memory_links` edge, (d) replay with no LLM driver available succeeds when provenance cache is populated and fails cleanly when it is not, (e) replay never calls the live `LlmDriver` (assert via a fake driver whose `complete` panics — replay must never invoke it), (f) reversal is idempotent: reverting an already-reverted proposal is a typed `AlreadyReverted` outcome, not a panic.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10. Split `ReplayDriver::replay` into helpers per event-kind handler if it grows.
- Single source of truth: replay re-applies `proposed_state` via the same memory store path used at original apply; reversal uses the same path with `prior_state`. No parallel write paths.
- Error handling: typed `ReplayError` (snapshot missing, divergence detected, cached response missing, prior-state corrupt) and `ReverseError` (not yet applied, already reverted, prior-state missing). No bare `unwrap`.
- Naming: `ReplayDriver`, `ReplayMode`, `reverse`, `post_apply_state_hash`, `with_cached_responses`. No `Manager`/`Helper`.
- Schema parity: `ProposalDecision::Reverted` covered by migration; `post_apply_state_hash` column added to the `MemoryConsolidated` event payload schema.
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- Observability: replay emits a `tracing::info_span!("replay", mode, events_replayed, divergences)`; every divergence emits a `tracing::error!` with the diverging memory id and both hashes. Reversal emits `tracing::info_span!("reverse_proposal", proposal_id)`.
- Doc citation: file-top doc comment cites `## 6. Consolidation Engine` "Consolidation modes" and `## Non-Negotiable Product Properties` (per `lattice/CLAUDE.md` § Markdown Heading References).
