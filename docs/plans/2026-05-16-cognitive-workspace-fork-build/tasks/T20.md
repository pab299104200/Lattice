# T20 — Phase 3 — memory_links + memory_evidence + memory_accesses + memory_scores tables

**Phase:** 3
**Type:** backend
**Model class:** balanced
**Depends on:** T19
**Spec anchor:** [§Memory Graph](../../2026-05-16-cognitive-workspace-fork-plan.md#4-memory-graph)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task makes memory links, evidence, access history, and usefulness scores first-class records rather than columns or JSON blobs on the `memories` table. Each becomes its own table with typed Rust APIs that the rest of Phase 3 (CRUD, streams, migration, tests) and later phases (verification, retrieval, consolidation) build on. The spec is explicit that link records must carry source, target, type, strength, reason, evidence event, creator, timestamps, and verification status — none of which are expressible as denormalized columns. Without this task, contradiction and supersession cannot be queried as graph edges, retrieval cannot explain inclusion, and verification cannot recheck individual evidence anchors.

## Spec excerpts that drive this task

> "Memory links should be first-class records: source memory, target memory or graph node, link type, strength, reason, evidence event, created by, created at, verification status."

> "Required link types: `supports`, `contradicts`, `supersedes`, `refines`, `generalizes`, `specializes`, `co_occurs_with`, `derived_from`, `applies_to`, `validated_by`, `invalidated_by`."

> "Core tables: … `memory_links`, `memory_evidence`, `memory_accesses`, `memory_scores` …"

## Steps

1. In `memory_graph/links.rs`, define `pub enum MemoryLinkType` with the 11 spec variants: `Supports`, `Contradicts`, `Supersedes`, `Refines`, `Generalizes`, `Specializes`, `CoOccursWith`, `DerivedFrom`, `AppliesTo`, `ValidatedBy`, `InvalidatedBy`. Derive serde + canonical wire names.
2. Define `pub enum MemoryLinkTarget { Memory(MemoryId), File(FileId), Symbol(SymbolId), DocSection(DocSectionId), Test(TestId) }` so a link can point at a memory or a workspace-graph node.
3. Define `pub struct MemoryLink { link_id: MemoryLinkId, source: MemoryId, target: MemoryLinkTarget, link_type: MemoryLinkType, strength: f32, reason: String, evidence_event_id: Option<EventId>, created_by: Actor, created_at: DateTime<Utc>, verification_status: VerificationStatus }`. `strength ∈ [0, 1]`; deny construction outside that range.
4. In `memory_graph/evidence.rs`, define `pub struct MemoryEvidence { evidence_id: MemoryEvidenceId, memory_id: MemoryId, event_id: Option<EventId>, anchor: EvidenceAnchor, captured_at: DateTime<Utc>, captured_by: Actor }` where `EvidenceAnchor` is an enum over `FileSpan { file: FileId, byte_start: u64, byte_end: u64, sha256: [u8; 32] }`, `SymbolRef(SymbolId)`, `DocSection { id: DocSectionId, sha256: [u8; 32] }`, `TestResult { test: TestId, passed: bool, run_event: EventId }`, `EventReference(EventId)`. The `sha256` fields enable exact-span verification in Phase 7.
5. In `memory_graph/accesses.rs`, define `pub struct MemoryAccess { access_id: MemoryAccessId, memory_id: MemoryId, accessed_at: DateTime<Utc>, accessed_in_event: EventId, accessor: Actor, inclusion_reason: String, was_used: Option<bool>, downstream_outcome_event: Option<EventId> }`. `was_used` is filled in later by retrieval-outcome correlation; nullable on initial write.
6. In `memory_graph/scores.rs`, define `pub struct MemoryScore { memory_id: MemoryId, score_kind: ScoreKind, value: f32, computed_at: DateTime<Utc>, computed_from_window: Duration, sample_size: u32 }` with `ScoreKind = { UsefulnessPrior, RecentUsefulness, RetrievalAccuracy, RegressionRisk }`. Multiple score rows per memory per kind track score history; the current value is the most recent row per (memory_id, score_kind).
7. Extend `memory_graph/schema.sql` (or add per-table SQL files included by the migrator) with:
   - `memory_links` columns: `link_id TEXT PRIMARY KEY`, `source_memory_id TEXT NOT NULL REFERENCES memories(memory_id)`, `target_kind TEXT NOT NULL`, `target_id TEXT NOT NULL`, `link_type TEXT NOT NULL CHECK(link_type IN (...))`, `strength REAL NOT NULL CHECK(strength BETWEEN 0 AND 1)`, `reason TEXT NOT NULL`, `evidence_event_id INTEGER NULL`, `created_by_kind TEXT NOT NULL`, `created_by_detail TEXT NULL`, `created_at INTEGER NOT NULL`, `verification_status TEXT NOT NULL`.
   - `memory_evidence` columns: `evidence_id TEXT PRIMARY KEY`, `memory_id TEXT NOT NULL REFERENCES memories(memory_id)`, `event_id INTEGER NULL`, `anchor_kind TEXT NOT NULL`, `anchor_json TEXT NOT NULL`, `captured_at INTEGER NOT NULL`, `captured_by_kind TEXT NOT NULL`, `captured_by_detail TEXT NULL`.
   - `memory_accesses` columns: `access_id TEXT PRIMARY KEY`, `memory_id TEXT NOT NULL REFERENCES memories(memory_id)`, `accessed_at INTEGER NOT NULL`, `accessed_in_event INTEGER NOT NULL`, `accessor_kind TEXT NOT NULL`, `accessor_detail TEXT NULL`, `inclusion_reason TEXT NOT NULL`, `was_used INTEGER NULL`, `downstream_outcome_event INTEGER NULL`.
   - `memory_scores` columns: `memory_id TEXT NOT NULL REFERENCES memories(memory_id)`, `score_kind TEXT NOT NULL`, `value REAL NOT NULL`, `computed_at INTEGER NOT NULL`, `computed_from_window_secs INTEGER NOT NULL`, `sample_size INTEGER NOT NULL`. Primary key `(memory_id, score_kind, computed_at)`.
8. Add indexes per spec §Storage Design "memory link source/target indexes": `idx_memory_links_source(source_memory_id)`, `idx_memory_links_target(target_kind, target_id)`, `idx_memory_links_type(link_type)`; for evidence: `idx_memory_evidence_memory(memory_id)`, `idx_memory_evidence_event(event_id)`; for accesses: `idx_memory_accesses_memory_time(memory_id, accessed_at)`, `idx_memory_accesses_event(accessed_in_event)`; for scores: implicit by PK plus `idx_memory_scores_memory_kind(memory_id, score_kind, computed_at DESC)`.
9. Define typed CRUD APIs per module: `pub fn insert_link / get_links_from / get_links_to / get_links_by_type`; `pub fn insert_evidence / get_evidence_for`; `pub fn record_access / list_accesses_for / mark_used`; `pub fn write_score / latest_score / score_history`. All use `rusqlite::params!`.
10. Define typed errors per module (`MemoryLinkError`, `MemoryEvidenceError`, `MemoryAccessError`, `MemoryScoreError`) and a unifying `MemoryGraphError` re-exported from `mod.rs`.
11. In `memory_graph/links_tests.rs`, write tests covering: every link type round-trips through write/read; strength outside [0, 1] is rejected with a typed error; target dispatch to memory vs. graph-node round-trips; evidence anchors round-trip including byte-span sha256; accesses can be marked used after the fact; score history orders newest-first.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: every Rust field maps to a column; CHECK constraints encode enum invariants.
- No silent error handling — `[0, 1]` range violations, target-kind mismatches, and JSON decode failures all return typed errors.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: `rusqlite::params!` everywhere; foreign keys enforced (`PRAGMA foreign_keys = ON`); no `format!` of SQL.
- Use `tracing::trace_span!` on writes and `tracing::warn!` on FK violations.
