## Goal

This task delivers the large-repo performance test suite that proves the hot-path budgets from Phases 1 and 2 hold at realistic scale, not only on the toy repo the unit tests use. Spec §Phase 1 sets identity resolution at ≤2ms P99; spec §Phase 2 sets event write at ≤5ms P99 on `prepare_change` and `get_context_capsule`; spec §Non-Negotiable Product Properties bans "unbounded graph traversal, payload growth, or event-log scans on hot paths." This task takes the fixture repos captured by T66 (large-repo fixtures from the benchmark suite — multiple languages, multiple repo sizes) and exercises every hot path against them, asserts the P99 budgets, and writes the results to `large_repo_results.json` for the metrics dashboard and R87 review.

## Steps

1. Read spec §Phase 1 DoD (identity ≤2ms P99), §Phase 2 DoD (event write ≤5ms P99), §Non-Negotiable Product Properties (no unbounded scans), §Phase 11 deliverables, and §Measurable Success Criteria so the budgets and the targets are pinned before any code.
2. Confirm the T66 fixture corpus exists; if absent, this task documents the gap and opens a follow-up. The harness assumes T66 ran; the fixture set must include at least: small-Rust (~5k files), medium-TypeScript (~25k files), large-polyglot (~100k files), and one extra-large fixture (~250k files) to stress event-log scans.
3. Create `daemon/crates/lattice-core/src/hardening/large_repo_tests.rs` (new module under a new `hardening/` directory; register it from `lib.rs`). Annotate the tests with `#[ignore]` so default `cargo test --workspace` does not slow CI; the verification command uses `-- --include-ignored` to opt in.
4. For each fixture, implement a test that:
   - Spins up a daemon instance against a temp `.lattice/` directory rooted at the fixture.
   - Performs a full incremental indexing pass and records the wall-clock duration.
   - Runs N (≥1000) hot-path tool invocations for each of `prepare_change`, `get_context_capsule`, `expand_context`, `impact_from_diff`, `diagnose_failure`, `search_symbols`, `find_relevant_tests`.
   - Computes per-tool P50, P95, P99 latency and asserts P99 ≤ the budget from the spec: identity resolution ≤2ms, event write ≤5ms, total tool latency must beat the baseline captured in T04 by the documented initial targets from §Measurable Success Criteria (30% fewer discovery calls is a quality metric, not latency — but the latency must not regress vs T04 baselines).
   - Asserts no graph traversal scanned more than the documented neighborhood budget; assert no event-log query scanned more than the documented index slice; both via debug counters exposed by the daemon's tracing.
5. Capture P50/P95/P99 per tool per fixture into a JSON report at `docs/plans/2026-05-16-cognitive-workspace-fork-build/baselines/large_repo_results.json`. Schema mirrors `baseline_metrics.json` from T04 with an extra `fixture` field. The file is committed to the repo so R87 and R89 can diff against later runs.
6. Add a test that exercises event-log compaction at large scale: write 1M events into the log, trigger compaction per spec §Storage Design "event log compaction", measure compaction wall-clock and assert the daemon remains responsive (hot-path P99 within budget while compaction runs).
7. Add a test that exercises payload spillover: write a series of events whose payloads exceed the inline threshold from T13 (or wherever the threshold was defined in Phase 2), assert spillover row writes succeed and reads round-trip without breaking the hot-path budget.
8. Run `cd daemon && cargo build --release` then `cd daemon && cargo test -p lattice-core --lib hardening::large_repo_tests -- --include-ignored` and confirm every test passes. Capture the output and update the JSON report.

## Coding-standard checks

- File length ≤800 lines (split per fixture if it exceeds, e.g. `large_repo_tests/rust.rs`, `large_repo_tests/typescript.rs`).
- Function length ≤50 lines per test; setup factored into helpers.
- Tests as documentation: each test name describes the budget it asserts (e.g. `test_prepare_change_p99_under_5ms_on_large_polyglot_fixture`), per `coding.md` §Tests as documentation.
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- No silent error handling — every measurement that fails the budget panics with a message naming the tool, fixture, observed P99, and budget.
- Observability: tests emit `tracing` events under a dedicated target so the JSON report can be regenerated from the trace if needed.
- Doc citation: comments cite `## Phase 1: Unified Identity Model` (DoD), `## Phase 2: Event Log Substrate` (DoD), and `## Non-Negotiable Product Properties` for the budget rules (per `lattice/CLAUDE.md` Markdown Heading References).
