# T21 — Phase 3 — Memory stream taxonomy + scope enforcement helpers (deny-by-default)

**Phase:** 3
**Type:** backend
**Model class:** balanced
**Depends on:** T19
**Spec anchor:** [§ViLoMem](../../2026-05-16-cognitive-workspace-fork-plan.md#vilomem)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task carves the memory graph into the typed streams the spec calls out (code topology, workflow episodes, failure patterns, semantic repo claims, architecture decisions, user/team preferences, docs and contract state) and provides the scope-enforcement helpers that make sure every query is deny-by-default: a query without an explicit scope returns nothing, and cross-scope leakage (branch-only memory appearing in another branch, user memory leaking across users) is impossible at the store API. Without this task, retrieval (Phase 4) cannot ask "give me only architecture-decision memories for this branch" and verification (Phase 7) cannot enforce the spec's scope-leakage control.

## Spec excerpts that drive this task

> "ViLoMem's transferable idea is dual-stream memory and retrieval. For code agents, generalize that to multiple typed memory streams: code topology, workflow episodes, failure patterns, semantic repo claims, architecture decisions, user/team preferences, docs and contract state. Each stream should have its own ranking rules, freshness semantics, and consolidation policy."

> "scope: session, branch, repo, user, organization"

> "Risk: user/org/branch memories leak into wrong workspaces. Control: scope-aware queries, enforced filters in store APIs, and negative tests."

## Steps

1. In `memory_graph/streams.rs`, define `pub enum MemoryStream` with the seven spec streams: `CodeTopology`, `WorkflowEpisodes`, `FailurePatterns`, `SemanticRepoClaims`, `ArchitectureDecisions`, `UserTeamPreferences`, `DocsAndContractState`. Derive serde + canonical wire names.
2. Define `pub fn classify_stream(class: MemoryClass, assertion_type: AssertionType) -> MemoryStream` as the deterministic mapping the rest of the system uses. Examples per spec semantics:
   - `Observation` / `Constraint` / `Pattern` / `AntiPattern` → `SemanticRepoClaims` or `CodeTopology` depending on whether the linked targets are symbols/files (code topology) or higher-level claims.
   - `WorkflowOutcome` / `Procedure` → `WorkflowEpisodes`.
   - `FailurePattern` → `FailurePatterns`.
   - `Decision` / `ArchitectureInvariant` → `ArchitectureDecisions`.
   - `Preference` → `UserTeamPreferences`.
   - `DocsContract` → `DocsAndContractState`.
   - `OpenQuestion` → `WorkflowEpisodes` (open questions belong to the active workflow stream until resolved into another class).
   - `CounterMemory` → the stream of the memory it counters; if that memory is unknown, default to `SemanticRepoClaims` and flag via tracing.
   Document the table in the module doc and cite `docs/architecture/2026-05-16-memory-graph-schema.md`.
3. Define per-stream policy records: `pub struct StreamPolicy { stream: MemoryStream, freshness_default: FreshnessPolicy, consolidation_window: Duration, default_scope: MemoryScope, ranking_profile: RankingProfileRef }`. `RankingProfileRef` is a string id that retrieval (Phase 4) will resolve; do not embed ranking logic here.
4. Provide `pub fn default_policy(stream: MemoryStream) -> StreamPolicy` returning the policy table referenced in the architecture doc.
5. In `memory_graph/scope.rs`, define `pub struct ScopeFilter` as a typed builder: `session(session_id)`, `branch(workspace_id, branch_ref)`, `repo(workspace_id)`, `user(user_id)`, `organization(org_id)`. Builder methods consume `self` and return `Self`.
6. Define `pub fn ScopeFilter::to_sql_predicate(&self) -> ScopePredicate` returning a parameterized WHERE clause and bind vector keyed against the denormalized `scope_*` columns from T19. Never `format!` user-supplied scope ids into SQL.
7. Define `pub fn ScopeFilter::enforce_subset(of: &ScopeFilter) -> Result<(), ScopeError>` so a Phase 4 retrieval request cannot widen scope beyond what the session is allowed to see (e.g. a branch-scoped request cannot read org-scoped memory unless explicitly opted in by policy).
8. Implement deny-by-default in the store APIs by requiring `ScopeFilter` on every read path: `MemoryStore::query(..., scope: &ScopeFilter)` — calling without a scope is a compile error. For internal admin/migration paths add `MemoryStore::query_unscoped_admin(...)` with a function name that makes the contract explicit and document it as test-or-migration-only.
9. Define `pub enum ScopeError { Underspecified, CrossScopeViolation { requested: MemoryScope, allowed: MemoryScope }, IdentityMismatch { field: &'static str } }`.
10. In `memory_graph/scope_tests.rs`, write tests covering: a query without a scope fails to compile or returns `Underspecified` (depending on whether the API takes `&ScopeFilter` directly); branch A's memory never appears in branch B's results; user A's memory never appears in user B's results; org-scoped memory only appears when explicitly enabled by `ScopeFilter::with_organization`; `enforce_subset` rejects widening; `classify_stream` mapping is exhaustive over `MemoryClass` (use a `match` with no `_` arm so the compiler enforces this).
