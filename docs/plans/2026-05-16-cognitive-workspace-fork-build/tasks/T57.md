## Goal

This task redesigns the four discovery workflow tools (`get_context_capsule`, `get_docs_capsule`, `find_relevant_tests`, `impact_from_diff`) on top of the Phase 1–7 substrates so that each tool returns a compact bundle by default with deliberate expansion handles, rather than dumping broad slices of files. Spec §Non-Negotiable Product Properties requires "every workflow bundle is compact by default with deliberate expansion handles" and spec §Phase 8 DoD requires workflows that "produce enough context to implement and verify changes without broad file dumping." Without this redesign, discovery calls remain the dominant tool-call cost in Phase 9 metrics and the success criterion "40 percent fewer irrelevant file reads" cannot be met.

## Spec excerpts that drive this task

> "Every workflow bundle is compact by default with deliberate expansion handles." (spec §Non-Negotiable Product Properties)

> "Phase 8 Deliverables: redesigned versions of context, change planning, scenario tracing, failure diagnosis, docs retrieval, test selection, impact analysis, and playbook generation; workflow composition over graph, event, memory, and working-memory substrates."

> "Every tool response should support: compact rendering, full structured JSON, context handles, stable expansion targets, budget controls, diagnostic explanations where useful." (spec §MCP Surface)

> "Definition of done: common coding tasks require fewer manual discovery calls; workflows produce enough context to implement and verify changes without broad file dumping."

## Steps

1. Read spec §Phase 8 and §MCP Tool Contract Principles in full. Reuse the shared bundle types from T56 (`WorkflowBundle`, `Pivot`, `MemoryHighlight`, `EventEpisode`, `RiskNote`, `ExpansionHint`) so all eight Phase 8 tools share one schema surface; do not duplicate the structs in `workflow_v2/`.
2. Implement `get_context_capsule` in `workflow_v2/context_capsule.rs`: take a free-form task or file/symbol anchor list, run the Phase 4 intent classifier + anchor resolver, retrieve compact candidates from graph + memory + docs + events, score them, and produce a compact bundle with at most N pivots (default 8, configurable via budget control). Each pivot must carry an inclusion reason and a stable expansion handle. Support `mode: "focused" | "compact" | "full" | "diagnostic"` per spec §MCP Surface render modes.
3. Implement `get_docs_capsule` in `workflow_v2/docs_capsule.rs`: anchor on doc sections rather than code symbols, traverse `documents` and `mentions` edges to surface adjacent prose and ADRs, and include code anchors that the cited sections reference. Output bundle must distinguish "doc primary" pivots from "code-referenced" pivots so the consumer knows where the authoritative text lives.
4. Implement `find_relevant_tests` in `workflow_v2/relevant_tests.rs`: accept either a file/symbol set or a diff, traverse `tested_by` edges in the Phase 1 graph, combine with `co_changed_with` evidence from the event log, score by graph proximity + past test-failure frequency, and return ranked test files with the verification command needed to run each (e.g. `cargo test -p X --lib mod::tests::test_name`). Spec §Measurable Success Criteria targets 90 percent correct relevant-test recommendation on curated tasks — the API must record per-recommendation provenance so T69 regression tests can measure recall.
5. Implement `impact_from_diff` in `workflow_v2/impact_from_diff.rs`: accept a diff or list of changed files/symbols, walk dependent edges (`calls`, `imports`, `implements`, `extends`, `type_ref`, `depends_on`) up to a bounded depth (spec §Non-Negotiable Product Properties forbids unbounded traversal on hot paths), attach affected tests via `tested_by`, attach affected docs via `documents`, and surface high-impact warnings as `RiskNote`s.
6. Each tool must emit `AssistantTaskStarted`, `ToolCalled`, `ContextBundleReturned`, and `MemoryRetrieved` events via the Phase 2 `EventWriter`. Hot-path budget per spec §Phase 2 DoD: ≤5ms P99 event-write overhead on `get_context_capsule`.
7. Each tool must register a stable context handle in `rpc/context_cache.rs` so `expand_context` can fetch the next delta cheaply per spec §MCP Surface "stable expansion targets" and spec §First Implementation Slice "Compact memory inclusion reasons in existing workflow tools."
8. Register the four `workflow_v2` tools in `daemon/crates/lattice-daemon/src/rpc/mcp.rs`; keep legacy implementations registered with deprecation flags per the T02 compatibility policy.
9. In `workflow_v2/discovery_workflows_tests.rs`, write tests that: (a) round-trip each tool's request/response through serde; (b) assert default render mode is compact and bundle size stays under the configured budget; (c) assert `get_context_capsule` returns expansion handles that `expand_context` can dereference; (d) assert `find_relevant_tests` recovers known golden tests for fixture repos; (e) assert `impact_from_diff` bounded-traversal cap is enforced; (f) assert no stale/contradicted memory appears without a stale label.
