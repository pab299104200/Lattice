# T22 — Phase 3 — Migration importer from existing Lattice memory rows

**Phase:** 3
**Type:** backend
**Model class:** advanced
**Depends on:** T19, T20, T21
**Spec anchor:** [§Phase 3: Memory Graph Storage](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-3-memory-graph-storage)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task migrates every row from the legacy `memories` table (the 80+ column table referenced in the context inventory) into the redesigned `memories`, `memory_links`, `memory_evidence`, `memory_accesses`, and `memory_scores` tables. Migration is idempotent, restartable, audited, and verifiable: every source row produces exactly one destination memory record plus zero-or-more derived link/evidence/access rows, all with provenance back to the source row id. Without this task, Phase 3 ships a parallel schema that the daemon cannot use without losing every existing memory; with it, the substrate switches over cleanly and the Phase 0 fork-or-extend decision is honored end-to-end.

## Steps

1. Inventory the legacy `memories` table columns by reading the existing `memory/store.rs`. For each column, decide its destination: a column on the new `memories` table, a row in `memory_links`, a row in `memory_evidence`, a row in `memory_accesses`, a row in `memory_scores`, or "dropped with rationale recorded."
2. Write the column-mapping table in `docs/architecture/2026-05-16-memory-migration-guide.md` under `## Column mapping`. For every legacy column: destination, transform (if any), default value when null, drop rationale (if dropped). This table is the authoritative source — code references this section by heading.
3. In `memory_graph/migration.rs`, define `pub struct MemoryMigrator { source_conn: Arc<Mutex<rusqlite::Connection>>, dest_conn: Arc<Mutex<rusqlite::Connection>>, batch_size: usize, dry_run: bool }`.
4. Implement `MemoryMigrator::plan(&self) -> Result<MigrationPlan, MigrationError>` returning row counts per source table, per destination table, plus any skipped rows with reasons. The plan is rendered into the report before any write happens; this is the operator's chance to abort.
5. Implement `MemoryMigrator::run(&self, plan: &MigrationPlan) -> Result<MigrationReport, MigrationError>`:
   1. Open a transaction on `dest_conn`.
   2. Iterate legacy rows in batches of `batch_size`.
   3. For each legacy row: construct the destination `MemoryRecord` (assigning `MemoryClass` and `AssertionType` per the column-mapping table; assigning `MemoryStream` via `streams::classify_stream`; resolving `MemoryScope` from legacy `freshness_policy` + workspace context).
   4. Insert the new `memories` row.
   5. Extract embedded link/evidence/access/score data from legacy JSON blobs and insert into `memory_links`, `memory_evidence`, `memory_accesses`, `memory_scores`.
   6. Record provenance: every destination row carries a `created_by = MigrationFrom { source_row_id }` actor variant so the migration's outputs are distinguishable from runtime writes.
   7. Commit the transaction at the end of each batch so a crash mid-migration can resume.
   8. Emit a `MemoryConsolidated` event per migrated record (via the T13 writer) with payload `{ source_row_id, dest_memory_id }` so the event log records the migration.
6. Implement idempotence: maintain a `migration_progress` table tracking `last_migrated_source_row_id`; on `run`, skip rows already migrated. A second `run` after a successful first should produce zero new inserts.
7. Implement `dry_run` mode: when true, build every destination row in memory and validate it against the new schema constraints, but do not write. Output a report identical to a real run so operators can diff plan vs. execution.
8. Define `MigrationError` typed enum: `SourceUnreadable`, `DestinationUnready`, `RowMappingFailed { source_row_id, reason }`, `ConstraintViolation { table, detail }`, `IdempotenceConflict { source_row_id }`, `EventEmitFailed(EventWriteError)`.
9. Add a CLI entry point `lattice memory-migrate --dry-run` / `--apply` so operators can run the migration outside the daemon's automatic boot path; document it in the migration guide.
10. In `memory_graph/migration_tests.rs`, write tests covering:
    - empty source DB migrates to empty destination with no errors.
    - a curated set of legacy rows (one per memory class, plus a row with links, a row with evidence, a row with accesses) migrates exactly once; row counts match the plan.
    - a second run after a successful first run is a no-op.
    - a crash simulated by panicking mid-batch leaves the destination in a consistent state (the partial-batch transaction rolls back); a follow-up run completes the migration.
    - `dry_run` produces a report identical to the real run but writes nothing.
    - rows that cannot be mapped (e.g. unknown legacy class string) are reported under `RowMappingFailed` and the rest of the migration proceeds; the migration does not halt on the first bad row.
11. Write `docs/architecture/2026-05-16-memory-migration-guide.md` with sections: `## Overview`, `## Column mapping`, `## Idempotence`, `## Dry-run`, `## CLI usage`, `## Recovery from partial migration`, `## Rollback procedure` (point at the Phase 0 storage policy's rollback path). The doc is the authoritative reference; cite headings from code.

## Coding-standard checks

- File length ≤800 lines per file (split the column-mapping helpers into a sub-module if the file approaches the limit).
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: the column-mapping table is the single source of truth; the code reads the destination shape from `MemoryRecord` so drift fails to compile, not silently at runtime.
- No silent error handling — unmapped rows produce typed `RowMappingFailed` and appear in the report; never `unwrap`.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: `rusqlite::params!` everywhere; transactional batches with explicit `commit`; `PRAGMA foreign_keys = ON` during migration.
- Use `tracing::info_span!("memory_migration", batch = ?)`, `tracing::warn!` on `RowMappingFailed`, `tracing::error!` on `ConstraintViolation`.
