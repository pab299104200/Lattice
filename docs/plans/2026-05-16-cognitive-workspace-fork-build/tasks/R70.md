## Goal

This task delivers the Phase 9 review. It asserts that the metrics collection module (T65), the cross-language benchmark fixture repository (T66), the MCP-wired metrics surface (T67), the regression dashboard + CLI report (T68), and the regression coverage tests (T69) together satisfy spec §Phase 9 deliverables and definition of done, and that each spec §Measurable Success Criteria initial target is either met by T69's tests or recorded as a `fail` finding triggering reopen. Without this review, Phase 10 (Human Review UI) proceeds against an unvalidated metrics layer and the success-criterion claims cannot be defended.

> "Phase 9 Deliverables: retrieval relevance metrics; memory usefulness metrics; context token efficiency metrics; stale/contradicted memory surfacing metrics; test-pass-after-plan metrics; repeated-failure reduction metrics; benchmark tasks with golden expected anchors; regression dashboard or CLI report."

> "Required metrics: tool calls per successful task; irrelevant files opened per task; relevant anchor recall; memory inclusion precision; memory later-used rate; stale memory surfaced rate; contradiction missed rate; tests recommended versus tests needed; workflow success after first plan." > "Definition of done: changes to retrieval, memory, and workflow behavior can be evaluated without relying on anecdote." (spec §Phase 9)

## Steps

1. Read spec §Phase 9 and §Measurable Success Criteria in full. Quote the "Required metrics" paragraph and the "Initial targets" paragraph verbatim at the top of the review.
2. Under `## Spec alignment`, walk every Phase 9 deliverable (retrieval relevance metrics, memory usefulness metrics, context token efficiency metrics, stale/contradicted memory surfacing metrics, test-pass-after-plan metrics, repeated-failure reduction metrics, benchmark tasks with golden expected anchors, regression dashboard/CLI report) and cite the implementing files from T65–T69. Flag any deliverable that is missing or partial.
3. Under `## Coding-standard alignment`, run a per-file check across `daemon/crates/lattice-core/src/metrics/`, `daemon/crates/lattice-daemon/src/rpc/metrics_surface.rs`, `daemon/crates/lattice-daemon/src/bin/lattice_report.rs`, and `daemon/crates/lattice-core/benches/cognitive_workspace_benchmark.rs`: file length ≤800 lines, function length ≤50 lines, nesting ≤3, cyclomatic ≤10, schema parity (every public type serde-derived), no `TODO`/`FIXME`/commented-out code, no unjustified `#[allow(...)]`, observability spans present, honest `None` reporting on missing data (no fabricated zeros). Record each violation with file:line.
4. Under `## Success-criteria coverage`, build a matrix of every spec §Measurable Success Criteria initial target (six rows: 30% discovery, 40% irrelevant reads, 80% memory precision, 0 stale-without-label, 0 contradicted-trusted, 90% test recommendation). For each row, cite the T69 `#[test]` name proving the target, the current measured value on the T66 fixtures, the baseline value from T04, and the pass/fail outcome. Any row without a passing test is a `fail` finding.
5. Under `## Findings`, summarize spec gaps, coding-standard violations, threshold-coverage misses, fixture coverage gaps (e.g. one language fixture missing a task class), honest-null violations, and any divergence between the T68 CLI report output and the T65 collector. Each finding cites file:line and the spec or standard it violates.
6. Run `cd daemon && cargo build --release` and `cd daemon && cargo test -p lattice-core --lib metrics` and `cd daemon && cargo test -p lattice-daemon --lib rpc::metrics_surface_tests` and `cd daemon && cargo bench --bench cognitive_workspace_benchmark -- --warm-up-time 1 --measurement-time 3`. Record each result in the review.
7. Under `## Verdict`, state `pass` or `fail` with a one-paragraph justification. If `fail`, name the specific tasks that must be reopened.
8. Save the review at `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R70-metrics.md` with the mandatory headings checked by verification commands.
