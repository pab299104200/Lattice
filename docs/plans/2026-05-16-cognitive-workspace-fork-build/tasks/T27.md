## Goal

This task delivers the first stage of the Phase 4 retrieval pipeline: a deterministic, feature-based classifier that reads a user task statement and assigns it one or more intent labels (debug, refactor, explain, add-feature, test, docs, migration, performance, review, etc.). The classifier is the input to every later retrieval stage — anchor extraction biases toward intent-relevant token shapes, candidate retrieval weights source mix by intent, and the scorer applies a `task-type compatibility` signal that requires this label to exist. Per spec §Ranking Complexity, the classifier must stay feature-based and inspectable before any learned policy is layered on top, so that ranking remains explainable for the lifetime of Phase 4.

(spec §Phase 4: Retrieval V1)

> "Risk: ranking becomes hard to reason about. Control: keep ranker feature-based and inspectable before any learned policy. Expose diagnostic scores." (spec §Ranking Complexity)

## Steps

1. Read `docs/plans/2026-05-16-cognitive-workspace-fork-plan.md` §Retrieval Engine pipeline step 1, §Phase 4 deliverables, and §Ranking Complexity in full so the inspectability constraint is internalized verbatim.
2. Enumerate the intent labels the classifier must emit, drawn from spec language and current workflow tool coverage: `debug`, `refactor`, `explain`, `add_feature`, `modify_feature`, `add_test`, `update_docs`, `migration`, `performance`, `review`, `unknown`. Document each label with a short doc comment naming the workflow tools that depend on it.
3. Create `daemon/crates/lattice-core/src/retrieval_v1/mod.rs` (new directory) that re-exports the classifier API and registers the module with `lib.rs`.
4. Implement `daemon/crates/lattice-core/src/retrieval_v1/intent.rs`: a pure-function classifier `classify_intent(task_text: &str) -> IntentClassification` that returns a primary label, optional secondary labels, per-feature scores, and the literal features that fired (lemma matches, imperative-verb hits, error-keyword hits, file/symbol token shapes, question-form hits). Features must be a finite, documented list — no learned weights, no opaque model — so the result is fully inspectable per §Ranking Complexity.
5. Surface a `diagnostics()` view on `IntentClassification` that returns `(label, contributing_features, score)` tuples for use by the diagnostic mode of T30 and the working-memory inspector of T36; this is the contract that lets the ranker explain why a label was chosen.
6. Migrate the existing heuristic intent inference in `query/engine.rs` to call the new classifier instead of duplicating logic; remove the old inline heuristic in the same commit per "single source of truth" in `coding.md`.
7. Add `daemon/crates/lattice-core/src/retrieval_v1/intent_tests.rs` covering: every label appears for at least one canonical task statement; ambiguous tasks return multiple labels with documented tie-break; empty/whitespace input returns `unknown` without panic; long input is truncated at a documented boundary without losing the leading verb; diagnostics output round-trips through serde.
8. Run `cd daemon && cargo build --release` and the verification test command; fix any clippy warnings in the new module before stopping.
