# T23 — Phase 3 — Memory graph CRUD + verification status transitions + idempotent writes

**Phase:** 3
**Type:** backend
**Model class:** balanced
**Depends on:** T19, T20
**Spec anchor:** [§Memory Graph](../../2026-05-16-cognitive-workspace-fork-plan.md#4-memory-graph)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task implements the public memory store API: create, read, update, delete, and the state-machine transitions over `VerificationStatus` (`unverified → in_review → verified`, plus `stale`, `contradicted`, `superseded`, `expired`, `invalidated`). Writes are idempotent on a caller-provided idempotency key so retries do not double-insert. Every status transition emits the right event via the T13 writer (`MemoryCreated`, `MemoryUpdated`, `MemoryInvalidated`, `MemoryConsolidated`) and records an evidence row pointing at the triggering event. Without this task, the redesigned schema has no callable API and Phase 4 retrieval has nothing to read.

## Spec excerpts that drive this task

> "Verification outputs: `verified`, `unverified`, `in_review`, `stale`, `contradicted`, `superseded`, `expired`, `invalidated`."

> "Memory links should be first-class records … verification status."

## Steps

1. In `memory_graph/store.rs`, define `pub struct MemoryStore { conn: Arc<Mutex<rusqlite::Connection>>, event_writer: Arc<EventWriter> }` with `MemoryStore::open(...)`.
2. Define the create API: `pub fn MemoryStore::create(&self, draft: MemoryDraft, idempotency_key: IdempotencyKey) -> Result<MemoryRecord, MemoryStoreError>`. `MemoryDraft` is `MemoryRecord` minus `memory_id`, `created_at`, `updated_at`, `usefulness_score`, `verification_status` (initial status is always `Unverified`). On insert, emit `MemoryCreated` event with payload `{ memory_id, class, stream, scope, idempotency_key }`. Insert evidence rows from `draft.initial_evidence`.
3. Implement idempotency: store `idempotency_key` in a `memory_idempotency` table mapping key → `memory_id`. On `create` with a key that already exists, return the existing record without inserting; never raise an error.
4. Define the read APIs (all take `&ScopeFilter` per T21):
   - `get(memory_id, scope) -> Result<MemoryRecord, MemoryStoreError>`.
   - `list_by_class(class, scope, limit) -> Result<Vec<MemoryRecord>, _>`.
   - `list_by_stream(stream, scope, limit) -> Result<Vec<MemoryRecord>, _>`.
   - `list_by_status(status, scope, limit) -> Result<Vec<MemoryRecord>, _>`.
   - Reads with no scope refuse to compile (`ScopeFilter` is required).
5. Define the update API: `pub fn update(&self, memory_id, patch: MemoryPatch, evidence: Option<MemoryEvidence>, idempotency_key: IdempotencyKey) -> Result<MemoryRecord, MemoryStoreError>`. `MemoryPatch` is the set of optional updatable fields (content, confidence, freshness_policy, validity_conditions, invalidation_triggers, scope) but NOT `verification_status` (use `transition_status`) and NOT `memory_id` (immutable). Emit `MemoryUpdated` event.
6. Define the delete API: `pub fn delete(&self, memory_id, reason: &str) -> Result<(), MemoryStoreError>`. Delete is soft: set `verification_status = Invalidated` and write a tombstone row; the original record is kept for replay. Emit `MemoryInvalidated` event.
7. In `memory_graph/transitions.rs`, define the verification state machine: `pub fn transition_status(store: &MemoryStore, memory_id: MemoryId, to: VerificationStatus, reason: &str, evidence: Option<MemoryEvidence>) -> Result<MemoryRecord, MemoryTransitionError>`. Allowed transitions per spec:
   - `Unverified → InReview` (verification job started)
   - `Unverified → Verified` (deterministic verification passed)
   - `InReview → Verified` (human approval or job completion)
   - `InReview → Stale` / `Contradicted` / `Expired` / `Invalidated` (review outcome)
   - `Verified → Stale` (file changed since verification)
   - `Verified → Contradicted` (counter-memory or contradicting link added)
   - `Verified → Superseded` (newer memory supersedes; `superseded_by` column populated)
   - `Verified → Expired` (TTL elapsed)
   - `Verified → Invalidated` (manual or trigger-based invalidation)
   - `Stale → Verified` (re-verification passed; evidence updated)
   - `Stale → Invalidated` (re-verification failed and not recoverable)
   - terminal: `Invalidated`, `Expired`, `Superseded` do not transition further.
   Any disallowed transition returns `MemoryTransitionError::DisallowedTransition { from, to }`.
8. Every transition writes an evidence row pointing at the triggering event and emits the right lifecycle event: `Verified`/`Stale`/`Contradicted`/`Superseded`/`Expired` use `MemoryUpdated`; `Invalidated` uses `MemoryInvalidated`; `MemoryConsolidated` is reserved for Phase 6 consolidation transitions.
9. Define `MemoryStoreError` typed enum: `NotFound(MemoryId)`, `ScopeViolation(ScopeError)`, `ConstraintViolation { detail }`, `Storage(rusqlite::Error)`, `Identity(IdentityError)`, `EventEmit(EventWriteError)`. Define `MemoryTransitionError` separately so callers can pattern-match on transition issues specifically.
10. In `memory_graph/store_tests.rs`, write tests covering: create → read round-trip; create with same idempotency key returns the existing record; update preserves immutable fields; soft-delete leaves the row readable as `Invalidated`; every legal transition is exercised; at least three illegal transitions are exercised and return `DisallowedTransition`; every transition emits the expected event (assert via `EventReader::tail`).

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: `MemoryDraft` and `MemoryPatch` reference only fields that exist on `MemoryRecord`; mutability of each field is encoded in the patch type, not via runtime checks.
- No silent error handling — every transition returns a typed error; event-emission failures roll back the SQL transaction (`?` from inside the txn).
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: every write wrapped in a transaction; `rusqlite::params!`; no SQL formatting.
- Use `tracing::info_span!("memory_store.transition", from = ?, to = ?)`.
