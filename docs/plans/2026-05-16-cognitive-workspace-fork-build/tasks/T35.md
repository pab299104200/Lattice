## Goal

This task implements every required operation on `WorkingMemoryState` from spec §5: `retrieve`, `summarize`, `filter`, `pin`, `evict`, `expand`, `compress`, `checkpoint`. Each operation mutates state in a documented, auditable way and pairs with a contract: every operation that drops or skips a memory must record the result in `excluded_memories` with a reason so the working-memory inspector (T36) can show what was intentionally left out. The operations integrate with Phase 4 retrieval (`retrieve` calls into the Phase 4 pipeline, `compress` invokes the shaper's compression policy, `pin` supplies the pin set the shaper honors).

## Steps

1. Re-read spec §5. Working Memory "Required operations" list and §Phase 5 Definition of Done to fix the contract for each operation.
2. Define an `Operation` trait or `WorkingMemoryOp` enum in `operations.rs` documenting the eight operations with one match arm per operation, so adding a ninth requires a deliberate type-system change.
3. Implement each operation as a free function `pub fn <op>(state: &mut WorkingMemoryState, args: <Op>Args, ctx: &OpContext) -> Result<<Op>Outcome>`, ≤50 lines each:
   - `retrieve(state, args, ctx)`: invokes the Phase 4 pipeline (intent → anchors → candidates → scoring → shaper) and merges the returned `RetrievalBundle` into `state.selected_memories`; every dropped candidate during shaper compression is captured in `state.excluded_memories` with its exclusion reason.
   - `summarize(state, args, ctx)`: returns a compact `WorkingMemorySummary` view (task, intent label, active file count, selected/excluded counts, budget usage, top hypotheses) for MCP display and event capture.
   - `filter(state, predicate, ctx)`: removes selected memories that fail `predicate`; removed entries move to `excluded_memories` with reason `"filtered: <predicate description>"`.
   - `pin(state, identities, ctx)`: adds identities to `state.budget_decisions.pinned_identities`; documented contract is that subsequent `compress` and shaper-driven trimming must not drop pinned identities.
   - `evict(state, identities, ctx)`: removes identities from `selected_memories`, records each in `excluded_memories` with reason `"evicted: <caller reason>"`; refuses to evict pinned identities unless `force=true`.
   - `expand(state, target, ctx)`: re-runs Phase 4 scoring against a widened candidate set centred on `target` (a `BundleResult` already in `selected_memories`) using its `expansion_handle`; new high-ranked candidates are appended to `selected_memories`.
   - `compress(state, budget, ctx)`: reuses the shaper's compression policy on `state.selected_memories`, honoring `pinned_identities`; dropped results move to `excluded_memories` with reason `"compressed: budget=<n> tokens"`.
   - `checkpoint(state, name, ctx)`: calls `state::save_checkpoint(state, name, conn)` and returns the `CheckpointId`.
4. Make every operation idempotent where the spec implies it: calling `pin` twice on the same identity is a no-op; `evict` on an absent identity returns `Ok` with a documented no-op outcome; `checkpoint` with the same name versions the entry, never silently overwrites.
5. Wire `OpContext` so it carries the SQLite connection, retrieval profile, identity resolver, and shaper handle once — operations never construct these themselves.
6. Surface every state mutation through a single internal helper `record_state_mutation(state, op_name, before_hash, after_hash, summary)` so T36's event capture has a single hook to wire `MemoryRetrieved` / `MemoryExpanded` events into.
7. Add `daemon/crates/lattice-core/src/working_memory/operations_tests.rs` covering: each of the eight operations is exercised; `retrieve` populates both `selected_memories` and `excluded_memories`; `pin` then `compress` proves pinned identities survive; `evict` of a pinned identity without `force` is refused; `filter` records the predicate description; `summarize` returns a non-empty view with the expected fields; `expand` increases the selected-memories count when the candidate pool widens; `checkpoint` returns an id whose `load_checkpoint` byte-matches the state.
8. Run `cd daemon && cargo build --release` and the verification test command; fix any clippy warnings before stopping.
