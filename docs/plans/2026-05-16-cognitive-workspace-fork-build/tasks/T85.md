## Steps

1. Read spec §Documentation Requirements in full so the eleven required documents are pinned. Cross-reference each with the existing architecture docs to identify which ones are net-new vs. consolidation-of-existing.
2. Create `docs/architecture/2026-05-16-successor-architecture-overview.md`. This is the front-door doc operators read first. Required headings: `## Overview`, `## Three substrates`, `## Identity model`, `## Storage layout`, `## Read paths`, `## Write paths`, `## Operational invariants`. Reference but do not duplicate the per-substrate design docs created below.
3. Create `docs/architecture/2026-05-16-memory-model-reference.md`. The authoritative reference for the memory graph. Required headings: `## Memory classes` (all classes from spec §4 including `CounterMemory`), `## Memory record fields` (every field from spec §4 with type, nullability, default), `## Memory link types` (all link types from spec §4 with reciprocity rules), `## Scope semantics` (session / branch / repo / user / organization), `## Verification status state machine`, `## Freshness policy`, `## Validity conditions and invalidation triggers`, `## Memory evidence`, `## Memory access history and usefulness scores`.
4. Create `docs/architecture/2026-05-16-event-log-design.md`. The authoritative reference for the event log. Required headings: `## Append-only invariant`, `## Event kinds` (all 20 from spec §3), `## Event envelope` (every field from spec §3), `## Payload spillover`, `## Compaction snapshots`, `## Replay semantics`, `## Hot-path budgets`, `## Workspace and session scoping`.
5. Create `docs/architecture/2026-05-16-consolidation-design.md`. The authoritative reference for the consolidation engine. Required headings: `## Job types`, `## Modes` (synchronous / background / manual-review / replay), `## LLM-driven consolidation` (proposal-only, provenance, queue depth, cost budgets per spec §6), `## Proposal apply and reject flow`, `## Reversibility`, `## Replay-safe execution`.
6. Create `docs/architecture/2026-05-16-retrieval-ranking-design.md`. The authoritative reference for retrieval. Required headings: `## Pipeline` (the ten-step pipeline from spec §7), `## Candidate sources`, `## Ranking signals` (all 13 from spec §7), `## Diagnostic mode`, `## Compact mode`, `## Inclusion reasons and expansion handles`, `## Forward compatibility with working memory`.
7. Create `docs/architecture/2026-05-16-verification-freshness-design.md`. The authoritative reference for verification. Required headings: `## Verification checks` (every check from spec §8), `## Verification outputs` (all eight statuses from spec §8), `## Incremental verification`, `## Graph-change triggers`, `## Branch and workspace scope enforcement`, `## Time-bound expiry`.
8. Create `docs/operator-guide/2026-05-16-operator-guide.md`. Operator-facing how-to. Required headings: `## Installation`, `## Initial setup`, `## Daily operations`, `## Review surface tour` (cross-link to the extension UI guide), `## Metrics dashboard`, `## Troubleshooting`. Include the `pkill -f lattice && cp daemon/target/release/lattice extension/bin/ && cp daemon/target/release/lattice ~/.vscode/extensions/lattice.lattice-0.1.0/bin/` deploy sequence from `lattice/CLAUDE.md` Build/Deploy.
9. Create `docs/operator-guide/2026-05-16-migration-from-lattice.md`. Migration guide. Required headings: `## Overview`, `## Migration steps` (one ordered checklist), `## Pre-flight checks`, `## Data preservation guarantees`, `## Rollback procedure`, `## Post-migration verification`. Reference the storage migration policy from T03 by heading.
10. Create `docs/operator-guide/2026-05-16-benchmark-evaluation-guide.md`. Benchmark how-to. Required headings: `## Overview`, `## Running baseline benchmarks`, `## Running large-repo benchmarks` (cross-link to T80 fixtures), `## Interpreting the metrics report`, `## Regression detection`, `## Initial targets` (the §Measurable Success Criteria initial targets verbatim).
11. Create `docs/operator-guide/2026-05-16-extension-review-ui-guide.md`. Extension review UI walkthrough. Required headings: `## Overview`, `## Opening the review panel`, `## Memory inbox`, `## Promotion queue and contradiction queue`, `## Stale view and evidence inspector`, `## Event trace and retrieval explanation`, `## Consolidation, indexing, and graph health`, `## Accept/reject workflow`. Cross-link to T71–T76 file paths.
12. For every doc, cite spec headings exactly per `lattice/CLAUDE.md` Markdown Heading References. Do not duplicate spec content; cite the heading and add interpretation only.
13. Confirm the MCP contract reference produced by T61 (Phase 8) is linked from the operator guide and the architecture overview. If T61 did not deliver a standalone file, this task documents the link to the relevant section in `mcp.rs` doc-comments or the inline tool documentation.
