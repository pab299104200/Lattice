## Goal

This task delivers the concurrency test suite covering parallel sessions, write contention against the event log and memory store, and the replay-safe execution invariant for consolidation jobs. Spec §3 makes the event log append-only and replayable; spec §6 requires consolidation to be "auditable, reversible, and test-covered" with "replay-safe job execution." Spec §Phase 11 deliverables list "concurrency tests" explicitly. Without this suite, race conditions in event ordering, double-applied consolidation jobs, or memory-link torn writes would only surface in production. This task forces those failure modes to happen in CI.

## Steps

1. Read spec §3 Event Log (append-only, replayable), §6 Consolidation Engine (replay-safe execution, proposal-only writes), §Phase 11 deliverables, and §Testing Requirements so the concurrency invariants are pinned.
2. Create `daemon/crates/lattice-core/src/hardening/concurrency_tests.rs` (alongside `large_repo_tests.rs` from T80) and register it in the new `hardening/mod.rs`. Mark slow tests `#[ignore]` to opt in via the verification command's `--include-ignored` flag.
3. Implement parallel-session tests:
   - N (≥32) tokio tasks each open a separate daemon session, write a stream of events (`AssistantTaskStarted`, `ToolCalled`, `ToolResult`, `ContextBundleReturned`, …), and read them back. Assert per-session event ordering is preserved.
   - Assert workspace scoping holds: events from session A do not appear in queries from session B except via cross-session queries that explicitly request them.
   - Assert no event id collisions across sessions.
4. Implement write-contention tests:
   - N parallel writers each append events to the same `events` table; assert the daemon serializes writes without dropping any (count in = count out) and that ordering within each writer is preserved.
   - N parallel writers each create memory records with overlapping classes/scopes; assert no duplicate stable ids; assert per-record invariants (confidence in [0,1], status valid) hold under contention.
   - N parallel writers each create `memory_links` rows referencing the same source memory; assert no link drops, no torn writes (every row has both source and target set or neither), and that the access-history counter increments by exactly N.
5. Implement replay-safe consolidation tests:
   - Seed an event log with a deterministic trace; run consolidation jobs (episode summary, procedure extraction, contradiction detection); record the resulting memory state.
   - Replay the same event log into a fresh daemon instance; run the same jobs; assert the resulting memory state is byte-identical (or, where LLM-driven, that the proposal records are identical aside from documented non-determinism placeholders such as `proposal_id`).
   - Apply a proposal twice (simulating retry); assert the second apply is a no-op (idempotent) rather than producing a duplicate write.
6. Implement reader-vs-writer tests: while N writers append events, a reader iterates the log and asserts it never observes a partial event, never observes events out of monotonic timestamp order within a single session, and that an iterator finishing observes a consistent snapshot.
7. Implement compaction-during-write tests: trigger an event-log compaction snapshot (per spec §Storage Design) while writers are still appending; assert no events lost, no events duplicated, and that the snapshot + post-snapshot log together replay to the same state as the pre-compaction log.
8. Run `cd daemon && cargo build --release` then `cd daemon && cargo test -p lattice-core --lib hardening::concurrency_tests -- --include-ignored` and confirm every test passes.

## Coding-standard checks

- File length ≤800 lines (split per concern if it exceeds, e.g. `concurrency_tests/events.rs`, `concurrency_tests/memory.rs`, `concurrency_tests/consolidation.rs`).
- Function length ≤50 lines per test; setup factored into helpers (shared daemon-instance factory, event-stream generator, memory-record builder).
- Tests as documentation: each test name describes the invariant it asserts (e.g. `test_parallel_writers_preserve_per_writer_ordering`, `test_consolidation_apply_is_idempotent`).
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- No silent error handling — every assertion failure panics with a message naming the scenario and the violated invariant.
- Observability: tests emit `tracing` events under a dedicated target so race conditions can be diagnosed from logs even when not reproducible locally.
- Doc citation: comments cite `## 3. Event Log`, `## 6. Consolidation Engine`, and `## Phase 11: Hardening` (per `lattice/CLAUDE.md` Markdown Heading References).
