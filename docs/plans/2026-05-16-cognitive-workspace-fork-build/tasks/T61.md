# T61 — Phase 8 — Tool surface audit + final MCP reference doc (collapse overlapping tools per spec §MCP discipline)

**Phase:** 8
**Type:** docs
**Model class:** advanced
**Depends on:** T56, T57, T58, T59, T60
**Spec anchor:** [§MCP Surface](../../2026-05-16-cognitive-workspace-fork-plan.md#9-mcp-surface)

## Goal

This task produces the audited final MCP tool surface for the cognitive workspace fork: an audit doc recording which tools were collapsed and why, and the canonical reference doc enumerating every tool the daemon ships, its render modes, expansion handles, budget controls, deprecation status, and shim policy. Spec §MCP Surface "Tool surface discipline" makes this audit binding: "ten new memory tools is a meaningful cognitive load for clients … The goal is the smallest surface that covers all assistant workflows. Consolidate before stabilizing the MCP contract." Without this task, the Phase 8 work ships an unaudited surface and Phase 9 metrics regress against the wrong set of tool names.

## Spec excerpts that drive this task

> "Tool surface discipline: ten new memory tools is a meaningful cognitive load for clients. Before shipping Phase 8, audit whether `propose_memory_evolution` + `apply_memory_evolution` can collapse into a single tool with an `action` parameter, and whether `verify_memory` + `explain_memory` can be unified. The goal is the smallest surface that covers all assistant workflows. Consolidate before stabilizing the MCP contract." (spec §MCP Surface)

> "Every tool response should support: compact rendering, full structured JSON, context handles, stable expansion targets, budget controls, diagnostic explanations where useful." (spec §MCP Surface)

> "Required workflow tools: `get_context_capsule`, `prepare_change`, `plan_edit`, `trace_scenario`, `diagnose_failure`, `find_relevant_tests`, `impact_from_diff`, `get_docs_capsule`, `get_backlinks`, `expand_context`, `get_working_set_context`, `get_repo_playbook`, `search_symbols`, `search_memory`, `record_workflow_outcome`." (spec §MCP Surface)

## Steps

1. Read spec §MCP Surface in full and quote the "Tool surface discipline" paragraph verbatim in `2026-05-16-mcp-surface-audit.md` as the framing for the audit.
2. In `2026-05-16-mcp-surface-audit.md`, write a `## Audit findings` section that lists every collapse decision made during Phase 8: (a) `propose_memory_evolution` + `apply_memory_evolution` → unified `propose_memory_evolution` with `action` parameter (per T58); (b) `verify_memory` + `explain_memory` → unified `verify_explain_memory` with `mode` parameter (per T59); plus any further collapses identified while reviewing T56–T60. For each collapse, record: rationale, the spec sentence authorizing it, the deprecation shim policy, and the shim-removal deadline.
3. In `2026-05-16-mcp-surface-audit.md`, write a `## Collapsed tools` section that is a table or bullet list mapping each spec-nominal tool name to its actual implementation: `apply_memory_evolution → propose_memory_evolution(action="apply")`; `verify_memory → verify_explain_memory(mode="verify")`; `explain_memory → verify_explain_memory(mode="explain")`; and any others identified. Each row links to the implementing file under `daemon/crates/lattice-daemon/src/rpc/memory_v2/` or `workflow_v2/`.
4. In `2026-05-16-mcp-surface-audit.md`, write a `## Decisions not to collapse` section documenting any spec-nominal pair that was considered but NOT collapsed (e.g. `get_context_capsule` vs `get_docs_capsule` remain separate because they anchor on distinct identity types), with rationale.
5. In `2026-05-16-mcp-tool-reference.md`, write a `## Final tool list` section enumerating every tool the daemon ships after Phase 8. For each tool, include: canonical name, one-paragraph description, request schema summary, response schema summary, supported render modes (`compact` / `full` / `diagnostic` / handles), budget controls, emitted Phase 2 events, deprecation status, implementing file path. The list must include every spec §MCP Surface "Required workflow tools" and every new memory tool (counting the collapsed names) plus the deprecation shims kept active per the T02 compatibility policy.
6. In `2026-05-16-mcp-tool-reference.md`, add sections `## Render modes`, `## Expansion handles`, `## Budget controls`, `## Deprecation policy`, each citing the corresponding spec heading.
7. Cross-link `2026-05-16-mcp-surface-audit.md` ↔ `2026-05-16-mcp-tool-reference.md` and reference back to spec §MCP Surface, §MCP Tool Contract Principles, and the T02 compatibility policy by exact heading.
8. Confirm no spec §MCP Surface "Required workflow tools" entry is missing from the reference. Confirm no implemented tool is missing from the reference. The reference doc is single source of truth.
9. Confirm both docs respect the Cadres coding standard `## Hard limits` (file ≤800 lines); split into two docs is already mandated by the verification commands.
