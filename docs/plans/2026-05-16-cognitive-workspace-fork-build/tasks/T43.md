# T43 — Phase 6 — LLM provenance (model + prompt hash + response hash) + queue bounds + cost budgets

**Phase:** 6
**Type:** backend
**Model class:** advanced
**Depends on:** T42
**Spec anchor:** [§Consolidation Engine — LLM-driven consolidation](../../2026-05-16-cognitive-workspace-fork-plan.md#6-consolidation-engine), [§Phase 6: Consolidation Engine](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-6-consolidation-engine)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task makes every LLM-driven consolidation proposal from T42 auditable, reproducible, and bounded. It adds the provenance record (model name + prompt hash + response hash attached to each proposal), enforces the spec's bounded-queue-with-warning behavior at the LLM-job submission point, encodes per-job-type cost and latency budgets, and publishes the budget rationale as an architecture doc the operator can consult. It also nails down the malformed/failed-response contract: prior memory MUST remain unchanged and a `ConsolidationFailed` event MUST be emitted. Without this task, T42's LLM jobs would be reproducible only by luck and budget overruns would propagate silently.

## Spec excerpts that drive this task

> "each job records its model, prompt hash, and response hash as part of the proposal provenance so outputs are auditable and reproducible"

> "consolidation queue depth must be bounded; when the queue is full, new jobs are dropped with a log warning rather than stalling the daemon"

> "cost and latency budgets for LLM consolidation should be documented per job type before Phase 6 begins; jobs exceeding budget must fall back to deterministic approximations or skip with a stale flag"

> "failed or malformed LLM responses must leave the prior memory state unchanged and emit a consolidation failure event"

## Steps

1. Read spec §Consolidation Engine "LLM-driven consolidation" bullets 4, 5, and 6 verbatim and copy into the top-of-file doc comment on `llm/provenance.rs` and `llm/budget.rs`.
2. In `consolidation/llm/provenance.rs`, define `pub struct LlmProvenance { model: String, prompt_sha256: [u8; 32], response_sha256: [u8; 32], prompt_token_count: u32, response_token_count: u32, latency_ms: u32, called_at: DateTime<Utc> }`. Implement `LlmProvenance::record(driver_name, prompt_bytes, response_bytes, prompt_tokens, response_tokens, latency)` that hashes both blobs with SHA-256 (using the existing `sha2` crate or workspace-pinned equivalent).
3. Extend `ConsolidationProposal` with `provenance: Option<LlmProvenance>` (deterministic proposals leave it `None`; LLM jobs set it). Add a migration adding `provenance_json TEXT NULL` to `consolidation_proposals`.
4. In `consolidation/llm/budget.rs`, define `pub struct LlmBudget { max_prompt_tokens: u32, max_response_tokens: u32, max_latency_ms: u32, max_cost_micro_usd: u32 }` and `pub enum BudgetOutcome { Within, ExceededFallback(DeterministicFallback), ExceededSkipWithStale }`. Per spec: exceeding budget either falls back to a deterministic approximation (episode → T40 deterministic template; procedure → no-op; contradiction → deterministic supersession candidate from T41) or skips and flags affected memory as `stale`.
5. Provide a per-job-kind `BudgetCatalog::for_kind(kind) -> LlmBudget` returning the budgets documented in step 8 below. The catalog reads from `LatticeConfig` so operators can override; defaults are pinned in code AND mirrored verbatim in the architecture doc.
6. Extend the `BoundedJobQueue` from T39 with per-kind sub-quotas: when an LLM job's queue slice is full, drop the new job with a `tracing::warn!` carrying `kind`, `current_depth`, `max_depth`, `workspace_id`. Emit a `ConsolidationFailed` event with `error_kind = QueueFull` so the failure is auditable in the event log, not just the tracing stream.
7. Wire provenance into every LLM job's success path (`EpisodeSummaryJob`, `ProcedureExtractionJob`, `ContradictionDetectionJob`, `FailurePatternJob` — defined in T42): on a well-formed response, construct `LlmProvenance::record(...)` and attach it to the proposal before enqueuing. On a malformed/failed/budget-exceeded path, leave prior memory state unchanged and emit `ConsolidationFailed` with the right `error_kind`.
8. Write `docs/architecture/2026-05-16-consolidation-llm-budgets.md` with the mandatory headings and content: `## Scope`, `## Per-job budgets` (a table: job_kind | max_prompt_tokens | max_response_tokens | max_latency_ms | max_cost_micro_usd | fallback_strategy), `## Bounded queue depth`, `## Failure handling` (malformed → ConsolidationFailed, prior state unchanged), `## Provenance record` (fields + hash algorithm + reproducibility guarantee), `## Operator overrides` (config keys), `## Spec citation` (link to `## 6. Consolidation Engine` "LLM-driven consolidation").
9. In `consolidation/llm/provenance_tests.rs`, write tests that: (a) successful job attaches `LlmProvenance` with deterministic SHA-256 hashes computed from prompt + response bytes, (b) re-running the same prompt and response yields the same hashes (reproducibility), (c) a budget overrun triggers `ExceededFallback` for episode/contradiction and `ExceededSkipWithStale` for procedure/failure-pattern per the catalog, (d) per-kind queue overflow drops the job, emits the warn log, and writes a `ConsolidationFailed` event, (e) the architecture doc exists and contains the required headings (sanity-grep from the test harness using `include_str!`).

## Coding-standard checks

- File length ≤800 lines per file (`budget.rs` should stay compact; split per-kind fallback strategies into helpers if it grows).
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10. `LlmProvenance::record` and `BudgetCatalog::for_kind` are straight-line.
- Single source of truth: budgets live in `BudgetCatalog`; the architecture doc mirrors the values but the catalog is canonical (note this in the doc).
- Error handling: typed `BudgetError`, `ProvenanceError`. Malformed-response, budget-exceeded, and queue-full are normal control-flow outcomes — each emits a `ConsolidationFailed` event before returning.
- Naming: `LlmProvenance::record`, `BudgetOutcome::ExceededFallback`, `BudgetCatalog::for_kind`. No `Helper`/`Manager`.
- Schema parity: `provenance_json` column maps to `Option<LlmProvenance>` via serde; migration covers both up and (no-op) down direction.
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- Observability: every drop and budget overrun emits a `tracing::warn!` carrying `workspace_id`, `kind`, `current_depth`, `max_depth` (drops) or `actual_tokens`, `budget_tokens` (overruns), and writes the matching `ConsolidationFailed` event.
- Doc citation: code comments cite `## 6. Consolidation Engine` "LLM-driven consolidation" bullets 4, 5, 6; the architecture doc links the same heading (per `lattice/CLAUDE.md` § Markdown Heading References).
