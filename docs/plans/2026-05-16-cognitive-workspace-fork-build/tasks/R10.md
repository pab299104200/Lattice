## Purpose

This review certifies that Phase 1 delivers a unified identity substrate that all later phases can build on without re-litigating: stable id types for every entity kind, a resolver that returns ambiguity diagnostics instead of arbitrary picks, identity payloads serialized in MCP responses with legacy compatibility, and a full correctness + P99 budget test matrix. It is the gate Phase 2 (event log) depends on because events that reference unstable names cannot be replayed.

## Review procedure

1. Run `cd daemon && cargo build --release` and confirm the full workspace compiles without new warnings.
2. Run `cd daemon && cargo test -p lattice-core --lib identity::tests` and `cd daemon && cargo test -p lattice-core --lib identity::resolver_tests`; record pass/fail per named test.
3. Run `cd daemon && cargo test -p lattice-core --lib identity::budget_tests -- --include-ignored` and record the measured P99 per budget test alongside the 2ms target and the baseline number from T04.
4. Run `cd daemon && cargo test --workspace -- identity::serialization rpc::identity_payload` to confirm the MCP wiring tests pass.
5. Open `kinds.rs` and verify all seven identity kinds exist (File, Symbol, Doc, Section, Event, Memory, ContextHandle) by literal grep for each struct name.
6. Open `ambiguity.rs` and verify `ResolveOutcome` has the three variants (`Unique`, `Ambiguous`, `NotFound`) and that `AmbiguityReport` carries a `disambiguation_hint`.
7. Open `serialization.rs` and `identity_payload.rs` and confirm legacy name fields are preserved alongside new identity payloads on at least one workflow tool response (per T02 compatibility policy).
8. Open `resolver_tests.rs` and confirm the ten spec-mandated test cases (renames, moves, duplicates, branch changes, legacy compat, event-ref round-trip) are present by name.
9. Run `wc -l` on every Phase 1 source file and confirm each is ≤800 lines.
10. Grep all Phase 1 files for `TODO`, `FIXME`, `XXX`, commented-out code, and unjustified `#[allow(...)]` attributes. Flag every hit.
11. Inspect resolver error types and confirm no bare `String` errors leak through the public API (every error is a typed `ResolveError` variant).
12. Cross-check that doc citations in module-level docs reference the exact `## Phase 1: Unified Identity Model` heading.

## Required sections in the review output file

The reviewer writes to `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R10-identity.md` with these mandatory headings (each must contain real findings, not "n/a"):

- `## Spec alignment` — phase-by-phase coverage matrix for Phase 1 deliverables (stable ids per kind, resolver, ambiguity diagnostics, MCP serialization, legacy compatibility shim, four test categories). One row per deliverable with evidence column citing the artifact and the literal test name or struct name.
- `## Coding-standard alignment` — line-by-line audit vs. hard limits: `wc -l` per file, forbidden token grep, suppression audit, naming audit on public API surface.
- `## P99 budget evidence` — measured P99 numbers from `cargo test -- --include-ignored` for every budget test, alongside the 2ms target and the relevant baseline number from `baseline_metrics.json`. Verdict per metric: `within budget` or `over budget`.
- `## Findings` — issues found, severity (`blocker`, `major`, `minor`), suggested follow-up tasks opened in this build (never deferred outside).
- `## Verdict` — `PASS`, `PASS-WITH-FOLLOWUP-TASK-Txx`, or `BLOCK` (with named blockers).
