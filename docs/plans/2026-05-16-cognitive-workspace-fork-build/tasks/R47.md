## Goal

This task is the Phase 6 backend review. It audits T39–T46 against the spec's consolidation contract, the §Non-Negotiable Product Properties bullets that consolidation directly touches (replayability, observability, no silent broad mutation), and the coding standard. The review must produce a verdict on whether Phase 6 is ready to ship and gate Phase 7 (T48 verification engine begins under R47). It records concrete evidence — file paths, function names, test names, log lines — for every claim. A pass/fail decision without cited evidence is not a review.

## Spec excerpts that drive this task

> Phase 6 DoD: "completed tasks produce useful episode memories; repeated successful traces produce procedural memories; consolidation is auditable, reversible, and test-covered."

> "No consolidation job may silently rewrite high-scope memory without preserving provenance and prior state."

> "LLM-driven jobs run only in background or manual review modes, never on the synchronous post-task hot path."

> "consolidation queue depth must be bounded; when the queue is full, new jobs are dropped with a log warning rather than stalling the daemon"

> "cost and latency budgets for LLM consolidation should be documented per job type before Phase 6 begins"

## Steps

1. Run the full Phase 6 test suite from the repo root: `cd daemon && cargo test -p lattice-core --lib consolidation` and capture the count of passing / failing tests per submodule.
2. Audit `T39.proposal_tests`, `T40.session_tests`, `T41.deterministic_tests`, `T42.llm_tests`, `T43.provenance_tests`, `T44.review_queue_tests`, `T45.replay_tests`, `T46.integration_tests` for behavior coverage; list any spec bullet not exercised by at least one test.
3. Audit `daemon/crates/lattice-core/src/consolidation/*` for the proposal-only invariant: grep for any direct memory-store write outside `ConsolidationProposal::apply` and `ReplayDriver::reverse`; any hit is a finding.
4. Verify the hot-path forbid: confirm `LlmJobContext` checks `mode != SynchronousPostTask` in every LLM job's `run` entry point AND that the runtime's dispatch layer enforces the same (defense in depth per T42 step 8).
5. Verify queue-bound behavior end-to-end: enqueue overflow test exists and exercises both the per-LLM-kind sub-quota (T43) and the top-level cap (T39); both paths emit `tracing::warn!` AND a `ConsolidationFailed` event.
6. Read `docs/architecture/2026-05-16-consolidation-llm-budgets.md` and verify: (a) per-job-kind budgets table is present with all four LLM job kinds, (b) fallback behavior is documented per kind, (c) provenance record format matches T43's `LlmProvenance` struct exactly, (d) the spec citation links `## 6. Consolidation Engine` "LLM-driven consolidation".
7. Audit coding-standard adherence across the consolidation module: file lengths via `wc -l`, function-length sampling (any function visibly over 50 lines), nesting depth on `BoundedJobQueue::enqueue`, `ConsolidationProposal::apply`, every `Job::run`. Record exceptions and whether they carry the one-line justification per `coding.md` §Hard limits.
8. Write the review at `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R47-consolidation.md` with the mandatory headings: `## Spec alignment`, `## Coding-standard alignment`, `## Proposal discipline`, `## LLM budget evidence`, `## Findings`, `## Verdict`. Each section cites concrete evidence (file paths, line ranges, test names, log lines). The `## Verdict` heading states `pass` or `fail` with a one-paragraph justification. Failures list a minimum-fix patch path so a follow-up task can address them.
