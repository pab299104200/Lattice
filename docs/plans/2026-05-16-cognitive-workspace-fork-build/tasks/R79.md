## Purpose

This review is the contract gate between the Phase 10 review UI and the daemon MCP surface that powers it. Every method on `ReviewRpcBridge` calls a tool registered on the daemon side; this gate verifies that every method has a matching tool, that the JSON shapes round-trip end to end, that the schema is documented and regression-tested, and that no surface added by Phases 6–9 was forgotten on the extension side. The gate exists because UI compile + lint cannot detect contract drift — only an integration test that sends a real request to a real daemon and asserts the response shape can. Spec §Non-Negotiable Product Properties demands "every public MCP contract is documented and regression-tested"; this review enforces that for the review UI surface.

## Review procedure

1. Enumerate every method exposed by `ReviewRpcBridge` and confirm each maps to a registered MCP tool in `daemon/crates/lattice-daemon/src/rpc/mcp.rs`. Any orphan method on either side is a blocker.
2. For every mapped pair, inspect the typed request and response shapes on the TypeScript side (`rpcBridge.ts`) and the corresponding Rust schema in `mcp.rs` (and its serde structs). Field-by-field comparison: type, required/optional, name. Drift is a blocker per `coding.md` §Schema parity.
3. Cross-check `docs/architecture/2026-05-16-mcp-compatibility-policy.md` (T02) — every review-UI tool is either `stable`, `additive`, or `redesigned-with-shim`; nothing is undocumented.
4. Create `extension/src/test/contract.test.ts` (this is the deliverable contract test). The test launches a real daemon process via the existing pattern in `extension/src/test/`, sends one round-trip request per review-UI bridge method, and asserts the response parses into the typed shape. Include happy-path requests and an error-path request per tool. Tests use the real daemon binary (`daemon/target/release/lattice`), not a mock.
5. Run the contract suite with `cd extension && npm install && npm run compile && npm test`. Confirm every round-trip passes. If the daemon binary is not present in `extension/bin/`, the test setup builds and copies per `lattice/CLAUDE.md` Build/Deploy: `cd daemon && cargo build --release && cp daemon/target/release/lattice extension/bin/`.
6. Confirm the contract test exercises every review-UI tool from `rpcBridge.ts`: memory listing, evidence inspection, promotion queue read + apply + reject, contradiction queue read + apply + reject, stale listing, verify_memory, event trace read, retrieval explanation read, consolidation queue read + retry, indexing health read, graph health read + recompute.
7. Grep `daemon/crates/lattice-daemon/src/rpc/mcp.rs` for the corresponding tool registrations and confirm each accepts the documented request shape and returns the documented response shape.
8. Cross-check that backward-compat shims from R64 (if any) are still in place: every legacy tool name continues to route to the new implementation.

## Required sections in the review output file

The reviewer writes to `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R79-contract-extension-daemon.md` with these mandatory headings (each must contain real findings, not "n/a"):

- `## Contract surfaces` — table of every `ReviewRpcBridge` method, the corresponding daemon tool name, the request shape, the response shape, and the spec citation. One row per method.
- `## Round-trip evidence` — for every method, the contract-test name in `extension/src/test/contract.test.ts` that exercises it; the test output snippet showing the request, the response, and the assertion that the typed shape parsed; the daemon log line showing the request was received.
- `## Schema surfaces` — TypeScript ↔ Rust field comparison table per tool. Columns: TS field, TS type, TS required, Rust field, Rust type, Rust required, parity verdict. Any drift is flagged.
- `## Findings` — issues found, severity (`blocker`, `major`, `minor`), suggested follow-up tasks. Follow-up tasks must be opened in this build (do not defer outside).
- `## Verdict` — `PASS`, `PASS-WITH-FOLLOWUP-TASK-Txx`, or `BLOCK` (with named blockers).
