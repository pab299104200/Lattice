## Goal

This task delivers steps 2 and 3 of the spec's retrieval pipeline: extract every literal anchor a user statement provides — file paths, symbol names, error strings, shell commands, API names, config keys — and resolve each into a stable graph identity using the Phase 1 identity resolver. Anchor resolution is the deterministic core of the pipeline; everything downstream (candidate retrieval, scoring, expansion handles) relies on the resolver returning canonical identities. Ambiguity must be surfaced, not hidden — the resolver returns the candidate set with disambiguation reasons so the scorer in T30 can weigh them and the diagnostic mode in T30/T36 can explain why each candidate was kept.

## Steps

1. Re-read spec §Retrieval Engine pipeline steps 2 and 3, and §Phase 1 identity resolver deliverable, so the inputs and outputs are aligned with the existing identity model.
2. Design the anchor taxonomy in a doc-comment table at the top of `anchors.rs`: `PathAnchor`, `SymbolAnchor`, `ErrorAnchor` (with optional stack frames), `CommandAnchor`, `ApiAnchor` (HTTP routes, RPC methods, MCP tool names), `ConfigKeyAnchor`. Each variant declares the regex/token shape it matches and the identity family it resolves to.
3. Implement `daemon/crates/lattice-core/src/retrieval_v1/anchors.rs`: pure-function extractor `extract_anchors(task_text: &str, intent: &IntentClassification) -> Vec<RawAnchor>` and resolver `resolve_anchors(raws: Vec<RawAnchor>, resolver: &IdentityResolver) -> Vec<ResolvedAnchor>`. Resolution returns the canonical identity, the candidate set when ambiguous, the ambiguity reason, and the source span in the task text.
4. Route every path normalization, symbol lookup, and doc-section lookup through the existing Phase 1 `IdentityResolver` API — do not reimplement these in `anchors.rs` (single source of truth per `coding.md`).
5. Bias extraction by intent: for `debug` intent, raise the error/stack-frame regex priority and accept commonly-occurring error idioms (`thread 'X' panicked at ...`, `error[E\d+]:`, `Traceback (most recent call last):`); for `refactor`/`add_feature`/`modify_feature`, raise symbol-name extraction; for `update_docs`, raise Markdown heading and `path/to/file.md#heading` anchor extraction. Document the bias rules inline with `## Retrieval Engine` heading citation.
6. Emit a `diagnostics()` view on `ResolvedAnchor` returning `(anchor_text, resolved_identity, ambiguity_reason, source_span)` so the scorer (T30) can apply `exact identifier match` weighting and the diagnostic mode can show why an anchor was matched or skipped.
7. Add `daemon/crates/lattice-core/src/retrieval_v1/anchors_tests.rs` covering: each anchor variant detected in canonical inputs; intent bias rerouting (debug inputs surface errors first); ambiguous symbol names return the full candidate set with reason; unknown paths resolve to a `PathAnchor::Unresolved` rather than panicking; resolver round-trip preserves source spans; serde round-trip for the diagnostics view; empty input returns an empty vector without panic.
8. Run `cd daemon && cargo build --release` and the verification test command; fix any clippy warnings before stopping.
