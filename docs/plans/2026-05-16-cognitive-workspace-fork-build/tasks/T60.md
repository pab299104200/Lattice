## Goal

This task introduces the three remaining new MCP tools from spec §MCP Surface: `consolidate_session` (trigger session-level consolidation producing episode/procedure/failure-pattern proposals), `get_memory_metrics` (return the assistant-usefulness signals required by spec §Phase 9), and `get_event_trace` (return a paginated event-log slice scoped by task/session/workspace for audit and replay). Together these three tools complete the new memory surface and make the underlying substrates inspectable from any MCP client. Without them, Phase 6 consolidation runs only autonomously, Phase 9 metrics surface nothing to assistants, and the Phase 2 event log is invisible — all violations of spec §Non-Negotiable Product Properties "every background consolidation pass is recoverable, replayable, and observable" and §MCP Tool Contract Principles.

## Spec excerpts that drive this task

> "New or redesigned memory tools: …`consolidate_session`, `get_memory_metrics`, `get_event_trace`." (spec §MCP Surface)

> "Consolidation modes: synchronous post-task consolidation for small task traces; background scheduled consolidation for larger histories; manual review mode for high-impact repo or organization memories; replay mode for rebuilding memory state from the event log." (spec §Consolidation Engine)

> "Required metrics: tool calls per successful task; irrelevant files opened per task; relevant anchor recall; memory inclusion precision; memory later-used rate; stale memory surfaced rate; contradiction missed rate; tests recommended versus tests needed; workflow success after first plan." (spec §Phase 9)

> "The full event stream should not be injected into prompts. It exists for retrieval, audit, replay, metrics, and consolidation." (spec §Event Log)

## Steps

1. Read spec §MCP Surface, §Consolidation Engine, §Phase 9, and §Event Log in full.
2. Implement `consolidate_session` in `memory_v2/consolidate_session.rs`. Accept `session_id: SessionId`, `mode: "post_task" | "background" | "manual_review" | "replay"` (defaults to `post_task`), and optional `budget_ms` for synchronous mode. Internally enqueue the appropriate Phase 6 consolidation jobs against the session's event slice; return a `ConsolidationReport` enumerating each proposal produced (episode summary, promoted procedure, promoted failure pattern, supersession candidate, duplicate detection) with proposal IDs that can be applied/rejected via the unified `propose_memory_evolution` from T58. Honor spec §Consolidation Engine "No consolidation job may silently rewrite high-scope memory without preserving provenance and prior state" — all outputs are proposals, never silent writes.
3. Implement `get_memory_metrics` in `memory_v2/get_memory_metrics.rs`. Accept optional `scope: session | branch | repo | user | organization`, optional `time_range`, and `signals: Vec<MetricSignal>` (defaults to all). Return the full spec §Phase 9 "Required metrics" set: `tool_calls_per_successful_task`, `irrelevant_files_opened_per_task`, `relevant_anchor_recall`, `memory_inclusion_precision`, `memory_later_used_rate`, `stale_memory_surfaced_rate`, `contradiction_missed_rate`, `tests_recommended_vs_needed`, `workflow_success_after_first_plan`. Source values from the T65 metrics module when present; fall back to `session_metrics` and event-log aggregations with an explicit `source` field on every value so the caller knows where each number came from. Never fabricate missing values — return `null` with a reason instead.
4. Implement `get_event_trace` in `memory_v2/get_event_trace.rs`. Accept `task_id | session_id | workspace_id` plus optional `kinds: Vec<EventKind>` filter, `since: DateTime<Utc>`, `until: DateTime<Utc>`, and pagination cursor. Return ordered envelopes from the Phase 2 reader, compact-by-default (one-line summary per event) with stable expansion handles for full payload retrieval. Enforce workspace boundary checks per spec §Non-Negotiable Product Properties — never return events from a different workspace.
5. All three tools must support compact + full + diagnostic render modes per spec §MCP Tool Contract Principles. `get_event_trace` diagnostic mode includes payload hashes and any spilled-payload row IDs for replay.
6. Each tool emits the appropriate Phase 2 events: `consolidate_session` emits `MemoryConsolidated`; `get_memory_metrics` emits a `ToolCalled` + `ToolResult` pair; `get_event_trace` emits `ToolCalled` + `ToolResult` (does not emit a re-entrant event for each returned envelope — that would create a feedback loop).
7. Register the three tools in `daemon/crates/lattice-daemon/src/rpc/mcp.rs`. No deprecation shims needed — these tool names exist only in the new surface.
8. In `memory_v2/admin_tools_tests.rs`, write tests that: (a) round-trip each tool's request/response through serde; (b) assert `consolidate_session` produces proposals (never direct writes), and assert proposals are addressable via `propose_memory_evolution`; (c) assert `get_memory_metrics` returns every spec-required signal name or an explicit `null` with reason; (d) assert `get_memory_metrics` never fabricates values; (e) assert `get_event_trace` enforces workspace boundary (cross-workspace request returns a typed error); (f) assert pagination cursor stability across calls; (g) assert each tool emits the correct Phase 2 events.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: `ConsolidationReport`, `MetricSnapshot`, `EventTracePage` derive `Serialize`, `Deserialize`, `Debug`, `Clone`; every public field has a doc comment; the `mode` enum on `consolidate_session` is serde-tagged with snake_case wire names; `MetricSignal` reuses the canonical Phase 9 enum from T65 once present.
- No silent error handling — workspace-boundary violations are typed errors; missing metrics are explicit `null` with a `reason` field, never zero.
- No `TODO`, `FIXME`, `XXX`, commented-out code; no unjustified `#[allow(...)]`.
- Public API names follow intent-over-mechanism naming (`MetricSnapshot::source`, not `MetricSnapshot::src`).
- For SQLite: queries go through Phase 2/3/6 APIs; no raw SQL in the RPC layer.
- Observability: each tool emits `tracing::info!` spans with `tool`, `scope`, `event_count` or `proposal_count` fields.
- Doc citation: cite spec headings `## MCP Surface`, `## Consolidation Engine`, `## Phase 9: Metrics And Evaluation`, and `## Event Log` in module doc comments.
