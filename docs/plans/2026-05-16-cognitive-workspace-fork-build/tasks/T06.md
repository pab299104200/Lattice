# T06 — Phase 1 — Identity type system (File, Symbol, Doc, Section, Event, Memory, Handle)

**Phase:** 1
**Type:** backend
**Model class:** advanced
**Depends on:** R05
**Spec anchor:** [§Phase 1: Unified Identity Model](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-1-unified-identity-model)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task introduces the unified identity type system that every later substrate (event log, memory graph, working memory, retrieval, verification) depends on. Spec §Phase 1 states "Identity must precede the event log. An event that references a file, symbol, or doc by unstable name cannot be reliably replayed or used for consolidation." The task delivers stable, encodable, decodable, hashable id types for each of the seven identity kinds plus the encoding/decoding rules that make them compact in MCP payloads. The existing `SymbolId { file, name, byte_offset }` is generalized into a common identity model.

## Spec excerpts that drive this task

> "Phase 1 Deliverables: stable ids for files, symbols, docs, sections, events, memories, and context handles; identity resolver for paths, symbols, headings, tests, and event refs; explicit identity serialization in MCP payloads; compatibility support for legacy name-based references; tests for duplicate symbol names, renamed files, moved sections, and branch changes."

> "Definition of done: every workflow output can be expanded through a stable identity; ambiguous names return ambiguity diagnostics instead of arbitrary matches; identity resolution adds no more than 2ms P99 to hot-path tool calls."

## Steps

1. Read the crate boundary plan from T03 to confirm whether identity lives in `daemon/crates/lattice-identity/` or `daemon/crates/lattice-core/src/identity/`. The files_expected list assumes the in-`lattice-core` module layout; if T03 chose a separate crate, mirror the file structure under that crate and update the workspace `Cargo.toml`.
2. Create `daemon/crates/lattice-core/src/identity/mod.rs` declaring the `kinds`, `encoding`, and `tests` submodules and re-exporting the public identity types.
3. In `daemon/crates/lattice-core/src/identity/kinds.rs`, define one struct per identity kind with the exact fields required by the spec node/event/memory model:
   - `FileId { workspace_id, repo_relative_path, content_hash }`
   - `SymbolId { file: FileId, qualified_name, byte_offset, kind }` (generalizing the existing `SymbolId`)
   - `DocId { workspace_id, repo_relative_path, content_hash }`
   - `SectionId { doc: DocId, heading_path: Vec<String>, byte_offset }`
   - `EventId { workspace_id, ulid }` (ULID for monotonic ordering)
   - `MemoryId { workspace_id, ulid }`
   - `ContextHandleId { workspace_id, session_id, ulid }`
4. Each id type derives `Clone, Debug, PartialEq, Eq, Hash, serde::Serialize, serde::Deserialize`. Implement `Display` to produce the compact MCP wire form.
5. Define a common `IdentityKind` enum and an `Identity` enum that wraps the seven kinds so any subsystem can hold a heterogeneous identity reference.
6. In `daemon/crates/lattice-core/src/identity/encoding.rs`, implement compact wire encoding rules: a stable string form (`file:<workspace>/<path>@<hash>`, `symbol:<file>#<qname>@<offset>`, `event:<workspace>/<ulid>`, etc.) and a decoder that round-trips. Reject malformed strings with a typed `IdentityDecodeError`.
7. Provide `From<old_SymbolId> for SymbolId` and a re-export under the prior path so existing callers continue compiling.
8. In `daemon/crates/lattice-core/src/identity/tests.rs`, write unit tests for: round-trip encoding for every kind; equality semantics; hash stability across process restarts (deterministic for same inputs); `IdentityDecodeError` cases (empty, missing prefix, malformed hash); `From<old_SymbolId>` migration.
9. Add the module to `daemon/crates/lattice-core/src/lib.rs` with `pub mod identity;` and document the substrate in a module-level doc comment that cites the spec heading.
10. Run `cd daemon && cargo build -p lattice-core` and `cd daemon && cargo test -p lattice-core --lib identity::tests` to confirm green.
