# T12 — Phase 2 — Append-only SQLite event tables + payload spillover + indexes

**Phase:** 2
**Type:** backend
**Model class:** advanced
**Depends on:** T11
**Spec anchor:** [§Storage Design](../../2026-05-16-cognitive-workspace-fork-plan.md#storage-design)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task creates the durable, append-only SQLite tables that back the event log: `events` for envelope rows and `event_payloads` for spilled payloads larger than the inline ceiling. It defines the migration runner that creates the schema on a fresh `.lattice/events.db`, and the indexes that make task, session, workspace, and branch scoped reads bounded. The spec requires the event log to be append-only and replayable; this task is where that invariant is encoded in the schema (no UPDATE/DELETE triggers, monotonic event_id PK). Without these tables, T13 (writer) and T14 (reader) have nowhere to land.

## Steps

1. In `events/schema.sql`, define the schema as a single migration file the runner can execute idempotently. Tables:
   - `events` columns: `event_id INTEGER PRIMARY KEY AUTOINCREMENT`, `event_uuid TEXT NOT NULL UNIQUE`, `workspace_id TEXT NOT NULL`, `branch TEXT NOT NULL`, `session_id TEXT NOT NULL`, `task_id TEXT NULL`, `actor_kind TEXT NOT NULL`, `actor_detail TEXT NULL`, `kind TEXT NOT NULL`, `ts_unix_micros INTEGER NOT NULL`, `payload_hash BLOB NOT NULL`, `summary TEXT NOT NULL`, `payload_inline BLOB NULL`, `payload_spill_id INTEGER NULL`, `references_json TEXT NOT NULL`, `schema_version INTEGER NOT NULL`. Foreign key: `payload_spill_id REFERENCES event_payloads(row_id)`.
   - `event_payloads` columns: `row_id INTEGER PRIMARY KEY AUTOINCREMENT`, `payload_hash BLOB NOT NULL UNIQUE`, `bytes BLOB NOT NULL`, `bytes_len INTEGER NOT NULL`, `created_ts_unix_micros INTEGER NOT NULL`. Content-addressed by hash so duplicate payloads dedupe naturally.
   - `event_schema_version` table for the migration runner (`version INTEGER PRIMARY KEY`, `applied_ts_unix_micros INTEGER NOT NULL`).
2. Add a deny-write trigger on `events` for UPDATE and DELETE so the table is append-only at the engine level, not only by convention: `CREATE TRIGGER events_no_update BEFORE UPDATE ON events BEGIN SELECT RAISE(ABORT, 'events table is append-only'); END;` (same for DELETE).
3. Add indexes:
   - `idx_events_task` on `(task_id, ts_unix_micros)` for task-scoped reads.
   - `idx_events_session` on `(session_id, ts_unix_micros)`.
   - `idx_events_workspace_branch` on `(workspace_id, branch, ts_unix_micros)`.
   - `idx_events_kind_ts` on `(kind, ts_unix_micros)` for kind-filtered scans.
   - `idx_event_payloads_hash` is the implicit UNIQUE on `payload_hash`.
4. In `events/migrations.rs`, define `pub fn run_migrations(conn: &mut rusqlite::Connection) -> Result<(), EventStoreError>` that creates the `event_schema_version` table, reads the current version, and applies `schema.sql` if version is below the target. Embed `schema.sql` via `include_str!`.
5. In `events/store.rs`, define `pub struct EventStore { conn: Mutex<rusqlite::Connection>, ... }` with `EventStore::open(path: &Path) -> Result<Self, EventStoreError>`. Configure WAL mode and `synchronous = NORMAL` consistent with the Phase 0 storage policy; document any deviation.
6. In `events/store.rs`, define low-level row APIs that T13 writer and T14 reader will sit on top of: `insert_envelope_row(...)`, `insert_or_get_payload(...)`, `query_events_by_task(...)`, `query_events_by_session(...)`, `query_events_by_workspace_branch(...)`. Every SQL string uses `rusqlite::params!`; no `format!` of SQL.
7. Define `EventStoreError` as a typed error enum (`Io`, `Sqlite`, `MigrationFailed`, `PayloadTooLarge`, `EnvelopeInvalid`) — never `anyhow::Error` at module boundaries.
8. In `events/store_tests.rs`, write tests against an in-memory or temp-file DB: schema applies on fresh DB; migration is idempotent on re-open; UPDATE/DELETE triggers reject writes with the expected error; payload spillover row-IDs round-trip; content-addressed dedupe collapses identical payloads to one row; indexes exist (`PRAGMA index_list`).
9. Confirm the table layout matches the migration policy doc from T03; if T03 prescribed different column names, update this task's schema to match before merge — never diverge.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: every column in `schema.sql` maps to a field on the T11 envelope/payload types; nullability matches `Option<T>`/`T` exactly.
- No silent error handling — every `rusqlite::Result` propagated as `EventStoreError`.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: every statement uses `rusqlite::params!`; no `format!`/`+`/`{}` interpolation of SQL strings; raw SQL lives in `schema.sql` not Rust source.
- Use `tracing::debug!` / `warn!` for migration steps, schema mismatches, and trigger rejections so operators can diagnose without reproduction.
