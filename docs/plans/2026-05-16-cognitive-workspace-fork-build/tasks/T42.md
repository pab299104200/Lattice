**Phase:** 6
**Type:** backend

**Spec anchor:** [§Consolidation Engine — LLM-driven consolidation](../../2026-05-16-cognitive-workspace-fork-plan.md#6-consolidation-engine), [§Phase 6: Consolidation Engine](../../2026-05-16-cognitive-workspace-fork-plan.md#phase-6-consolidation-engine)
**Standards:** Cadres coding standard; Lattice project rules (`/home/pete/cadres/lattice/CLAUDE.md`, `AGENTS.md`).

## Goal

This task implements the four LLM-driven consolidation jobs the spec calls out as inherently non-deterministic: episode-summary generation (richer than T40's deterministic template), procedure extraction from repeated successful workflows, contradiction detection across memories, and failure-pattern extraction from repeated diagnostics. The spec is explicit that these jobs MUST run only in background or manual-review modes, NEVER on the synchronous post-task hot path, and MUST emit proposals (never silent writes). This task ships the four job implementations and the LLM-driver abstraction; T43 layers provenance and budgets on top, T44 adds the manual-review queue for high-scope outputs, T45 makes the work replay-safe.

## Spec excerpts that drive this task

> "Several consolidation jobs (episode summary generation, procedure extraction, contradiction detection, failure-pattern extraction) cannot be implemented deterministically and require LLM inference."

> "LLM-driven jobs run only in background or manual review modes, never on the synchronous post-task hot path."

> "each LLM-driven job produces a proposal record, not a direct write; proposals require explicit apply or reject before altering durable memory"

> "failed or malformed LLM responses must leave the prior memory state unchanged and emit a consolidation failure event"

## Steps

1. Read spec §Consolidation Engine "LLM-driven consolidation" subsection in full; copy the six constraint bullets into the top-of-file doc comment on `llm/mod.rs`.
2. In `consolidation/llm/mod.rs`, define `pub trait LlmDriver { fn complete(&self, request: LlmRequest) -> Result<LlmResponse, LlmDriverError>; fn name(&self) -> &str; }` plus a `pub struct LlmJobContext { workspace_id, mode: ConsolidationMode, budget: LlmBudget }`. Enforce a runtime guard: every LLM job entry point asserts `ctx.mode != ConsolidationMode::SynchronousPostTask` and returns `Err(LlmJobError::ForbiddenOnHotPath)` otherwise.
3. In `consolidation/llm/episode.rs`, implement `EpisodeSummaryJob::run(ctx, task_slice)` — fetch the event slice for a completed task, build a structured prompt requesting an episode summary, call the `LlmDriver`, parse the response into an `EpisodeMemory` candidate, and emit a `CreateMemory` or `UpdateMemory` proposal through the T39 runtime. On malformed JSON or driver error, emit a `ConsolidationFailed` event (new event-kind handler, reusing the Phase 2 event log) carrying `job_id`, `kind`, `error_kind`, leave any prior memory untouched, and return early.
4. In `consolidation/llm/procedure.rs`, implement `ProcedureExtractionJob::run(ctx, workflow_id, occurrences)` — gather N≥3 successful traces of the same workflow shape, prompt the driver to extract the procedure (steps, preconditions, postconditions, tools used), and emit a `CreateMemory` proposal for a `ProcedureMemory`. Same malformed-response handling as episode.
5. In `consolidation/llm/contradiction.rs`, implement `ContradictionDetectionJob::run(ctx, candidate_pair)` — given two memories the deterministic pass flagged as overlapping with conflicting assertions, prompt the driver to confirm contradiction and explain why. Emit an `UpdateMemory` proposal that flips one to `contradicted` and links it to the contradicting memory via `memory_links`. Same malformed handling.
6. In `consolidation/llm/failure_pattern.rs`, implement `FailurePatternJob::run(ctx, diagnostic_cluster)` — given N≥2 `DiagnosticObserved` events with similar shape, prompt the driver to summarize the failure pattern and propose a `FailurePatternMemory`. Same malformed handling.
7. Every job's malformed-response branch emits the consolidation failure event before returning. Add a `ConsolidationFailedPayload` to `events::kinds` if Phase 2 did not already include it (cite T11's event-kind list); otherwise reuse the existing payload.
8. Register all four jobs in `consolidation/llm/mod.rs` so the runtime can dispatch by `ConsolidationJobKind`. Forbid synchronous mode at the dispatch layer in addition to the per-job guard (defense in depth).
9. In `consolidation/llm/llm_tests.rs`, write tests with a fake `LlmDriver` that: (a) returns a well-formed response → a proposal is enqueued and prior memory is unchanged until apply, (b) returns malformed JSON → a `ConsolidationFailed` event is emitted and no proposal is enqueued, (c) the driver returns an error → same as malformed, (d) every job called with `ConsolidationMode::SynchronousPostTask` returns `ForbiddenOnHotPath` and the driver was never called, (e) per-job structured output round-trips (episode, procedure, contradiction, failure-pattern) into their respective memory classes.

## Coding-standard checks

- File length ≤800 lines per file.
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10. Each `run` method is a short pipeline: guard → prompt → call → parse → propose-or-fail.
- Single source of truth: every proposal goes through T39; every event emission goes through the existing Phase 2 event writer; no parallel write paths.
- Error handling: typed `LlmJobError` covers `ForbiddenOnHotPath`, `DriverError(LlmDriverError)`, `MalformedResponse(String)`, `BudgetExceeded`. Malformed/error branches MUST emit a `ConsolidationFailed` event before returning. No silent failure paths.
- Naming: `EpisodeSummaryJob`, `ProcedureExtractionJob`, `ContradictionDetectionJob`, `FailurePatternJob`, `LlmDriver`. No generic `LlmHelper`/`Runner`.
- Schema parity: every job's proposed-state JSON deserializes cleanly into the matching `MemoryClass` struct from Phase 3 (verify in tests).
- No `TODO`, `FIXME`, `XXX`, commented-out code, or unjustified `#[allow(...)]`.
- Observability: every job emits a `tracing::info_span!("llm_consolidation", job_kind, workspace_id, mode, model_name)`; failure path also emits a `tracing::warn!` mirroring the `ConsolidationFailed` event payload.
- Doc citation: each job file cites the exact `## 6. Consolidation Engine` "LLM-driven consolidation" bullet it implements and the `## Phase 6: Consolidation Engine` DoD (per `lattice/CLAUDE.md` § Markdown Heading References).
