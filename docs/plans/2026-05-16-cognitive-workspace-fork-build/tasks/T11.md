# T11 — Phase 2 — Event model types (all 20 event kinds + envelope)

**Phase:** 2
**Type:** backend
**Model class:** balanced
**Depends on:** R10
**Spec anchor:** [§Event Log](../../2026-05-16-cognitive-workspace-fork-plan.md#3-event-log)
**Standards:** Cadres coding standard; Lattice project rules.

## Goal

This task introduces the Rust type system for the append-only event log substrate. It defines the `EventKind` enum covering all 20 spec event types, the shared `EventEnvelope` struct carrying workspace id, branch, session id, task id, actor, timestamp, stable references, payload hash, compact summary, and optional full payload location, plus the typed payload structs for each kind. Without these types, Phase 2 storage, writer, reader, and capture work has nothing to serialize. Every later phase (memory consolidation, verification, retrieval, metrics) depends on these typed records, so getting the model right now prevents downstream churn.

## Spec excerpts that drive this task

> "Required event types: `AssistantTaskStarted`, `ToolCalled`, `ToolResult`, `ContextBundleReturned`, `MemoryRetrieved`, `MemoryExpanded`, `PlanCreated`, `FileRead`, `PatchApplied`, `TestRunStarted`, `TestRunCompleted`, `DiagnosticObserved`, `UserCorrection`, `UserPreferenceObserved`, `WorkflowSucceeded`, `WorkflowFailed`, `MemoryCreated`, `MemoryUpdated`, `MemoryInvalidated`, `MemoryConsolidated`."

> "Events should carry: workspace id, branch, session id, task id, actor, timestamp, stable references to files, symbols, docs, events, and memories, payload hash, compact payload summary, optional full payload location."

> "The full event stream should not be injected into prompts. It exists for retrieval, audit, replay, metrics, and consolidation."

## Steps

1. Read spec §Event Log in full and copy the 20 event-kind list verbatim into a doc comment on `EventKind` so the enum is self-documenting.
2. Create `daemon/crates/lattice-core/src/events/mod.rs` exporting the module surface (`kinds`, `envelope`) and a top-level doc comment that points to `docs/plans/2026-05-16-cognitive-workspace-fork-plan.md` §Event Log.
3. In `events/kinds.rs`, define `pub enum EventKind` with the 20 variants in spec order: `AssistantTaskStarted`, `ToolCalled`, `ToolResult`, `ContextBundleReturned`, `MemoryRetrieved`, `MemoryExpanded`, `PlanCreated`, `FileRead`, `PatchApplied`, `TestRunStarted`, `TestRunCompleted`, `DiagnosticObserved`, `UserCorrection`, `UserPreferenceObserved`, `WorkflowSucceeded`, `WorkflowFailed`, `MemoryCreated`, `MemoryUpdated`, `MemoryInvalidated`, `MemoryConsolidated`. Derive `Serialize`, `Deserialize`, `Clone`, `Copy`, `Debug`, `PartialEq`, `Eq`, `Hash`. Implement `EventKind::as_str()` returning the canonical snake_case wire name used in storage.
4. In `events/kinds.rs`, define one typed payload struct per variant (e.g. `AssistantTaskStartedPayload`, `ToolCalledPayload`, `ToolResultPayload`, `ContextBundleReturnedPayload`, `MemoryRetrievedPayload` …). Each payload references prior identity types (`FileId`, `SymbolId`, `DocSectionId`, `EventId`, `MemoryId`, `ContextHandleId`) — never raw paths or names.
5. Define `pub enum EventPayload` wrapping all 20 payload structs so the envelope can carry any kind without dynamic dispatch.
6. In `events/envelope.rs`, define `pub struct EventEnvelope` with the spec-required fields: `event_id: EventId`, `workspace_id: WorkspaceId`, `branch: BranchRef`, `session_id: SessionId`, `task_id: Option<TaskId>`, `actor: Actor`, `timestamp: chrono::DateTime<Utc>`, `kind: EventKind`, `references: Vec<StableRef>`, `payload_hash: PayloadHash`, `summary: CompactSummary`, `payload_location: PayloadLocation`. Derive `Serialize`, `Deserialize`, `Clone`, `Debug`.
7. Define `StableRef` as an enum over `FileRef(FileId)`, `SymbolRef(SymbolId)`, `DocSectionRef(DocSectionId)`, `EventRef(EventId)`, `MemoryRef(MemoryId)`, `ContextHandleRef(ContextHandleId)` so every reference is identity-typed.
8. Define `PayloadLocation` as `Inline { bytes_len: u32 }` or `Spilled { row_id: i64 }` so T12 can decide spillover policy without changing the envelope.
9. Define `Actor` as `enum { Assistant { model: String }, User, Tool { name: String }, Daemon }`. Define `CompactSummary` as a newtype around `String` with a hard ceiling (e.g. 512 bytes) enforced at construction.
10. In `events/tests.rs`, write tests that round-trip each `EventKind` through serde, assert canonical wire names, and verify every payload struct serializes deterministically (sorted JSON keys) so payload hashing in T13 is stable.

## Coding-standard checks

- File length ≤800 lines per file (split `kinds.rs` if it grows beyond, e.g. one sub-module per kind family).
- Function length ≤50 lines, nesting ≤3, cyclomatic ≤10.
- Schema parity: every variant has a typed payload struct with serde derives; every non-private field has an explicit type and doc comment.
- No silent error handling — `Result` returned from `CompactSummary::new` is checked at every call site or annotated.
- No `TODO`, `FIXME`, commented-out code.
- For SQLite: not applicable here (T12 owns SQL); ensure no schema bytes leak into this task.
- Use `tracing` only where construction failure must be observable; types themselves are passive.
