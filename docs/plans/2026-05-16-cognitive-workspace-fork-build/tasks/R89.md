## Purpose

This is the final gate before the cognitive-workspace fork is declared shippable. It assembles three matrices that each prior review touched only locally: (1) spec coverage matrix — one row per spec §Phase asserting PASS/PASS-WITH-CAVEATS/BLOCK; (2) measurable success criteria matrix — one row per target from spec §Measurable Success Criteria initial targets, with the evidence file path proving the target was hit; (3) risk controls matrix — one row per risk from spec §Risks asserting the control is implemented and pointing to the artifact that proves it. The review concludes with a single binding `## Ship verdict`: PASS or BLOCK. The verification step runs the full daemon test workspace and the full extension build to confirm the system compiles, lints, tests, and ships clean from a fresh checkout.

## Review procedure

1. Walk every spec §Phase (0 through 11) and assemble the spec coverage matrix. For each phase, locate the review file that covered it, capture the verdict, and propagate PASS / PASS-WITH-CAVEATS / BLOCK into this matrix. Any BLOCK from a prior review propagates to BLOCK here unless the blocking finding was resolved by a later follow-up task documented in this build.
2. Walk every target from spec §Measurable Success Criteria → "Initial targets":
   - 30 percent fewer discovery tool calls on benchmark tasks
   - 40 percent fewer irrelevant file reads
   - 80 percent memory inclusion precision on curated memory benchmarks
   - zero trusted display of known contradicted memory
   - zero trusted display of known stale memory without stale label
   - 90 percent correct relevant-test recommendation on curated tasks
   For each, locate the evidence file (typically a benchmark report under `docs/plans/2026-05-16-cognitive-workspace-fork-build/baselines/` or a test name under `daemon/crates/lattice-core/src/hardening/` or `daemon/crates/lattice-core/src/intelligence/benchmark_tests.rs`). Record evidence file path + value observed + target met/missed.
3. Walk every risk from spec §Risks (Opaque Memory Mutation, Ranking Complexity, Event Log Growth, Stale Memory Leakage, Scope Leakage, Overfitting To Current Repo) and confirm the control documented in the spec is implemented and tested. For each, cite the implementation file and the test that proves the control.
4. Run the full verification suite from a clean state:
   - `cd daemon && cargo build --release` — full release build.
   - `cd daemon && cargo test --workspace` — full daemon test workspace.
   - `cd extension && npm run compile` — extension TypeScript compile.
   - `cd extension && npm run lint` — extension lint.
   - `cd extension && npm test` — extension test suite including R79's contract tests.
   Any failure blocks the ship verdict.
5. Confirm the deploy sequence from `lattice/CLAUDE.md` Build/Deploy works end-to-end: `pkill -f lattice && cp daemon/target/release/lattice extension/bin/ && cp daemon/target/release/lattice ~/.vscode/extensions/lattice.lattice-0.1.0/bin/`. Confirm the extension picks up the new binary.
6. Confirm R88's `## Explicit Deferrals` section is either empty or every deferral meets the reason+owner+date bar; any silent deferral blocks the ship verdict per `/home/pete/.claude/CLAUDE.md` execution philosophy.
7. Confirm every spec §Non-Negotiable Product Property is satisfied (cross-reference with R83 workspace-boundary tests, R81 concurrency tests, R82 recovery tests, R87 hardening evidence).
8. Confirm spec §Final Target is met: "make a coding agent feel like it is operating in a workspace that remembers accurately." This is the qualitative final test — assemble evidence from R70 metrics + R78 frontend + R79 contract round-trips to argue the system delivers on each of the nine final-target bullet points.

The reviewer writes to `docs/plans/2026-05-16-cognitive-workspace-fork-build/reviews/R89-final-readiness.md` with these mandatory headings (each must contain real content, not "n/a"):
