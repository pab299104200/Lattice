## Goal

This task delivers two test modules that enforce two of the spec's hardest invariants: partial indexes must degrade gracefully (no panics, no silent dropped results), and workspace boundaries must hold (no silent broad workspace reads bypassing ignore rules; no cross-workspace memory leakage). Spec §Non-Negotiable Product Properties states "no silent broad workspace reads that bypass ignore rules or workspace boundaries"; spec §Scope Leakage names "user/org/branch memories leak into wrong workspaces" as a risk whose control is "scope-aware queries, enforced filters in store APIs, and negative tests." This task provides those negative tests.

## Steps

1. Read spec §Non-Negotiable Product Properties (workspace boundary rule), §Scope Leakage (negative tests required), §Phase 11 deliverables, and `daemon/crates/lattice-core/src/workspace/` (or equivalent) so the boundary contract is pinned.
2. Create `daemon/crates/lattice-core/src/hardening/partial_index_tests.rs` covering:
   - **Syntax-error fixture**: a file containing valid code interleaved with sections that fail to parse; assert the indexer produces a partial graph (parsed sections present, failed sections marked as such), emits an `IndexFailure` event per file, and that queries against the partial graph return well-formed answers (no panics, no `unwrap` on missing nodes).
   - **Mid-parse interrupt**: simulate a parser timeout or panic on a single file; assert the indexer continues with the remaining files and the partial index remains queryable.
   - **Missing referenced file**: indexer encounters an `imports` reference whose target file is in the ignore list; assert the edge is created with a "target-ignored" marker, not silently dropped or attempted as a broad read.
   - **Stale-on-read**: after a file is modified but before re-index completes, queries return results marked with the old freshness timestamp; assert the freshness label is correct and the operator can detect the staleness without seeing stale claims as `verified`.
   - **Index-cold start**: query the daemon during the first incremental index pass; assert the partial-index responses include an explicit "indexing in progress" marker per spec §10 indexing-health view requirements.
3. Create `daemon/crates/lattice-core/src/hardening/workspace_boundary_tests.rs` covering:
   - **Ignore rule honored**: configure a workspace with `.gitignore`/`.latticeignore` rules; assert no file matched by the rules ever shows up in any query result. Repeat for `search_symbols`, `get_context_capsule`, `prepare_change`, `expand_context`, `impact_from_diff`, and `find_relevant_tests`.
   - **No broad workspace read**: a query whose anchors don't resolve must not silently fall back to reading the entire workspace. Assert the daemon returns a "no anchors resolved" error or empty result with a documented marker, never a 10k-file scan dump per `## Non-Negotiable Product Properties`.
   - **Cross-workspace memory scope leakage**: create memories in workspace A with scope `repo` and `user`; open workspace B and query for memories; assert `repo`-scoped memories from A do not leak into B, and that `user`-scoped memories appear only when explicitly opted in via the documented cross-workspace query parameter.
   - **Branch scope leakage**: in workspace A on branch `main`, create memories scoped to `branch=main`; switch to branch `feature/x`; assert branch-scoped memories from `main` do not appear unless the query explicitly requests cross-branch.
   - **Session scope leakage**: create memories scoped to session S1; in session S2 query for memories; assert session-scoped memories do not appear.
   - **Event workspace scoping**: events emitted in workspace A do not appear in event-trace queries from workspace B (per spec §3 envelope `workspace_id` field).
   - **Path-traversal attempt**: a query whose path argument contains `..` segments that resolve outside the workspace root must be rejected with an explicit error, not silently followed.
4. Each test asserts the negative invariant: the leaked / forbidden item does NOT appear. Tests use direct store-API calls plus full-stack tool calls so both layers are validated.
5. Run `cd daemon && cargo build --release` then `cd daemon && cargo test -p lattice-core --lib hardening::partial_index_tests` and `cd daemon && cargo test -p lattice-core --lib hardening::workspace_boundary_tests` and confirm every test passes.
