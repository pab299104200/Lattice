## Steps

1. Re-read spec §Phase 5 Deliverables to fix the exact test families required; each family has its own file.
2. Implement `daemon/crates/lattice-core/src/working_memory/budget_tests.rs` covering: `compress` honors `budget_decisions.token_cap`; over-budget retrieval truncates and sets `BudgetReport::truncated = true`; truncated results move to `excluded_memories` with reason `"compressed: budget=<n> tokens"`; budget changes between operations affect only subsequent operations, not retroactively; a synthetic huge candidate set respects per-source caps so working memory never grows unbounded.
3. Implement pinned-context regression tests inside `budget_tests.rs` (or split into a small `pin_tests` if file size demands): `pin` makes an identity survive `compress`; `pin` twice on the same identity is idempotent; `evict` on a pinned identity without `force=true` is refused with a clear error; `evict` with `force=true` records the pinned identity in `excluded_memories` with reason naming the force; pin survives `checkpoint`/`load_checkpoint` round-trip.
4. Implement eviction regression tests in `budget_tests.rs` (or split): `evict` of a present identity moves it to `excluded_memories` with the caller-supplied reason; `evict` of an absent identity returns Ok with a documented no-op outcome; `evict` does not emit an event when nothing changed (T36 hook respects no-op); `evict` followed by `retrieve` for the same identity re-includes it (eviction is not a permanent deny-list within a session).
5. Implement `daemon/crates/lattice-core/src/working_memory/checkpoint_tests.rs` covering: `checkpoint` returns a `CheckpointId` whose `load_checkpoint` produces a byte-identical state (verified via canonical-JSON SHA-256); two checkpoints with the same name produce distinct ids and both round-trip; loading an unknown checkpoint id returns a typed error; loading a checkpoint whose `state_version` is newer than the running daemon is rejected with a clear error; restoring a checkpoint resets `selected_memories`, `excluded_memories`, and `budget_decisions` together (they are coherent state, never restored partially).
6. Each test is ≤30 lines per `coding.md` "Tests as documentation"; setup is extracted into helpers when the assertion would otherwise share lines with setup.
7. Run both verification test commands; if any test depends on a fixture not built by T32, build the minimal helper in a `tests_common.rs` sibling (no duplicated workspace generation in two places).
8. Audit the entire file set for the standard `coding.md` violations (TODOs, suppressions, commented-out code, dead imports); fix in this same commit before stopping.
