## Issues encountered

### F1 (in-scope, fixed) — flaky log capture in `corruption_tests`

`test_truncated_event_log_file_reports_recovery_or_sqlite_error_without_panic` failed intermittently (~30–50% under parallel test execution; 0% with `--test-threads=1`) because `tracing`'s per-callsite Interest cache is keyed against the global subscriber, but `capture_logs` was installing a thread-local subscriber via `set_default`. Once another test's `tracing_subscriber::fmt::try_init()` installed a global default, the `info!` callsites in `EventStore::open` cached `Interest::Never` for the thread-local capture path. Rewrote `capture_logs` to use a process-wide global subscriber (installed once via `OnceLock`) that routes through a `ThreadLocalWriter`, restoring deterministic capture. 10/10 verification passes after fix; full hardening suite 43/43 pass.
