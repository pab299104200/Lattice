## Issues encountered

- The existing `memory_v2` surface was only partially integrated into the RPC crate. `rpc/mod.rs` was missing the `memory_v2` module export, and the new T60 tools were not registered in the MCP tool list or dispatcher.
- The existing `propose_memory_evolution(action=apply|reject)` path bypassed the canonical consolidation proposal apply/reject flow and would not correctly materialize T60 consolidation proposals. I replaced that path with the real `ConsolidationProposal::apply` / `reject` flow so T60 proposals are auditable and actionable through the required tool.
- `get_event_trace` needed stable pagination support from the event reader, so I added a bounded `EventReader::execute_page` API instead of doing ad hoc scans in the RPC layer.
- The daemon test target still emits pre-existing warnings in unrelated memory-v2 test files. They did not block T60 verification.
