## Issues encountered

1. **`MemoryVerificationStatus` does not derive `Hash`.** First compile attempt used `HashSet<MemoryVerificationStatus>` in the end-to-end test. Switched to `Vec<MemoryVerificationStatus>` + `contains(&value)` to avoid changing a `memory::model.rs` derive purely for a test. No behavior loss — the set is bounded to 8 variants.
2. **`MemoryScope` does not derive `Copy`.** First version of `base_memory` in the support module passed `scope` by value while also consulting it for workspace / branch / org id resolution, which triple-moved the value. Resolved by passing `&MemoryScope` to the helper functions and consuming the value only once into the final `Memory` struct.
3. **`PreToolUse` security hook flagged `eval_injection`.** The `security_reminder_hook.py` matches the substring `eval` followed by an open paren, which substring-matches `retri eval` followed by an open paren — i.e., the word "retrieval" followed by an open paren. First Write call to the contract test file was blocked; the hook saves session state so the second Write succeeded. No content change was needed — the hook is a false positive on this substring due to substring matching.
4. **Two `ScopeFilter` types, two `MemoryStore` types in the workspace.** `verification::scope_enforcement::ScopeFilter` is consumed by the legacy `memory::MemoryStore` that the live retrieval pipeline (`retrieval_v1::candidates`) reads through; `memory_graph::scope::ScopeFilter` is the typed-memory store's filter exercised by R25. The R55 gate is deliberately scoped to the path retrieval actually consumes today — the path that the §Non-Negotiable property "Every stale or contradicted memory is surfaced as such" runs through in production. The Findings section of the review documents this scoping decision.
5. **`retrieval_v1::candidates::retrieve_memory_links` reads via `query_unscoped_admin`.** This is named on the store side as "explicit unscoped path for migrations, snapshots, and legacy admin flows." It is not a contract failure at the surface this gate guards — the §Non-Negotiable property is stamped at `SurfacingPipeline::partition`, which the gate tests directly, and the workflow tools re-apply scope filtering at their own boundary. The review's Findings section calls this out as a Phase 8 integration consideration, not a gate-blocking violation.
