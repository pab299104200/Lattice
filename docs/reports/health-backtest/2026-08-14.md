## Headline: do the fact families predict defects?

A file is labeled defective when a fix-shaped commit touched it inside the
bounded horizon after a cut point. Every figure below ranks files by facts
known *at* the cut point only.

`PR-AUC` is only interpretable against the prevalence baseline in the same
row: a random ranker scores exactly the prevalence. `ROC-AUC` is the
probability that a defect-labeled file outranks a clean one, where 0.500 is
chance. `lift` is precision at the stated threshold divided by prevalence.

## Per-fact discrimination — the weight derivation for H3

Each fact ranked on its own against the same ground truth. `ROC-AUC` of
0.500 is chance. The derived weight is `max(0, roc - 0.500) * 2`, so a fact
at or below chance carries no weight; a fact measured *below* chance is
dropped rather than inverted, because flipping its sign would invent a signal
the producer never claimed.

`Coverage` is the share of scored files for which the fact had any value at
all. A low-coverage fact with a strong AUC is a narrow signal, not a strong
one.

## H1.2 label-quality audit

The ground truth above rests entirely on `looks_like_bug_fix`, a
subject-prefix heuristic. It is audited here against an independent signal:
commits whose diff touches both an existing test file and a production file.

**These two signals do not measure the same thing.** Real fixes often ship
without touching a test, and features often ship with one. Raw agreement and
Cohen's kappa are therefore expected to be low even when the classifier works
correctly, and a low kappa here is *not* evidence against the vocabulary. The
figure that carries the most evidence is enrichment: whether commits the
classifier calls fixes co-modify tests and production more often than commits
in general.

Enrichment below 1.000 is genuinely ambiguous. It can mean the vocabulary
admits commits that are not fixes — or it can mean the proxy is
*anti-correlated* with fix-ness in this corpus, which is what happens wherever
feature work ships with tests while bug fixes are one-line repairs. Only the
spot-review sample below separates those two readings, which is why the spec
requires one. Read them together.

| Measure | Value |
| --- | ---: |
| Commits audited | 2360 |
| Classified fix-shaped | 571 (24.2%) |
| Touching test + production | 1251 (53.0%) |
| Co-modification rate, fix-shaped commits | 70.8% |
| Co-modification rate, all other commits | 47.3% |
| **Enrichment** | **1.336x** |
| Raw agreement | 57.0% |
| Cohen's kappa | 0.167 |
| **Verdict (independent signal)** | **corroborated** |

### Recall: the fixes the classifier does not see

Precision is not the only way a labeler fails. `looks_like_bug_fix` inspects
only the *prefix* of a subject, so a commit that announces repair work
anywhere else goes unlabeled and its files are recorded as clean. The count
below is every rejected commit whose subject names repair work as a whole word
(`fix`, `bug`, `hotfix`, `regression`, `revert`, …), which is a lower bound on
what the prefix rule gives up.

| Measure | Value |
| --- | ---: |
| Recognised as fixes | 571 |
| Rejected but naming repair work | 108 |
| **Recall gap** | **15.9%** |

A large recall gap means the reported prevalence understates the true defect
rate and that files repaired by unrecognised commits are counted as clean.
That depresses measured precision — it does not inflate it — so the accuracy
figures in this report are conservative with respect to this failure mode.

2x2 table: fix-shaped and co-modifying 404; fix-shaped only 167; co-modifying only 847; neither 942.

## What H3 may and may not conclude

The `Derived weight` column of the per-fact table is the weight table H3
should adopt, and the held-out family result is the accuracy it should expect.
Any fact whose derived weight is zero measured at or below chance on this
evidence and must not be given a non-zero weight without new evidence.

On this evidence, adding git history and complexity facts improved ranking over graph facts alone: ROC-AUC 0.901 for graph+git+complexity against 0.785 for
graph-only, held out.

Limits on what this evidence supports:

- Ground truth is a subject-line heuristic. The independent signal judged it **corroborated**, and it leaves a **15.9% recall gap** — subjects naming repair work that its prefix-only matching rejects. Every accuracy figure inherits that classifier's error.
- A defect that was never fixed inside the horizon, or fixed with a subject the classifier does not recognise, is labeled clean. Recall is measured against detected fixes, not against defects.
- 30 cut points across 5 repositories is a small sample. Differences between families smaller than the spread across cut points are not evidence.
- The measurement is correlational. A fact that ranks defect-prone files well is not thereby a cause of defects, and the score must be presented as evidence, never as a prediction of a specific future failure.
